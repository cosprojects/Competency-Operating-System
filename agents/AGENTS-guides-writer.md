# AGENTS-guides-writer

Ролевой контракт агента разборов AXIONA COS. Читается перед прогоном, который наполняет
подробными учебными разборами знания и навыки из публикации.

## Задача

Для каждого знания или навыка из публикации собрать **подробный разбор** (3–5 разделов: что это;
зачем в работе; как применять по шагам; пример из источника; на что обратить внимание) строго
по найденному источнику и положить его в отдельный кластер разборов.

Разбор — не описание в одну строку (это `descriptions:agent`) и не материал-ссылка (это
`materials-agent`): это связный текст «погружения» для модалки знания/навыка.

## Конвейер

1. **План запросов** — LLM на батч из 15 пунктов: короткий RU-запрос (сущность + интент)
   и EN-термин. Точное длинное название — худший запрос (см. `docs/09-research/content-aggregation-pilot-2026-11-16.md`).
2. **Поиск** — Brave: сначала RU, EN только если русский поиск не дал пригодного источника;
   запасной короткий запрос, если длинная формулировка не нашла.
3. **Фильтр** — deny-list (вакансии, соцсети, маркетплейсы), эвристическая оценка домена и позиции.
4. **Загрузка и отбор** — страница → текст; порог тематической релевантности (совпадение названия
   пункта с заголовком/первыми абзацами), язык, объём, заголовки; до двух источников на пункт.
5. **Синтез** — JSON `{status, sections[]}` только по источнику; EN переводится по смыслу;
   при недостатке материала — `no_data` (в интерфейсе тогда определение + честная пометка).
6. **Валидатор** — 3–5 разделов, 180–1400 символов на раздел, 900–6000 всего, русский, без ссылок,
   без «уровня/оценки», без обрыва; одна попытка починки.
7. **Кеш** — поиск, страницы и ответы LLM в `data/guides/.cache`; повторный прогон почти бесплатный.
8. **Кластер** — `src/methodology/v1/guides/content/it.json`: `id → {status, sections, sources,
   generatedAt, promptVersion, review}`. Коммитится; `release:build` копирует его в
   `apps/web/src/content/generated/guides.json`, откуда `GET /api/guide` отдаёт разбор.

## Команды

```bash
npm run guides:agent -- --profession uxui --limit 2 --concurrency 2 --out data/guides/dry-run  # дымовой прогон
npm run guides:agent -- --profession uxui --all --skip-existing --concurrency 4                 # профессия целиком
npm run guides:agent -- --profession all --all --skip-existing --concurrency 5 --max-cost 12    # все профессии
npm run guides:audit                                                                            # аудит привязки к источнику
```

| Флаг | Смысл |
|---|---|
| `--profession <slug\|all>` | одна профессия или все (UX/UI идёт первой) |
| `--limit <n>` | первые n пунктов по кругу между компетенциями (по умолчанию 50) |
| `--all` | все пункты профессии (вместо `--limit`) |
| `--skip-existing` | не пересобирать пункты, которые уже в кластере; общие для профессий теги не дублируются |
| `--concurrency <1…8>` | сколько пунктов вести параллельно (запись кластера сериализуется) |
| `--max-cost <usd>` | потолок стоимости LLM на прогон (по умолчанию 1.5) |
| `--out <dir>` | каталог прогона (по умолчанию `data/guides/run-<scope>-<date>`) |

Требуется `BRAVE_API_KEY` и `DEEPSEEK_API_KEY` в корневом `.env.local` — npm-скрипт читает файл
сам; ключи не печатать. Прогон пишет прогресс в stderr: `[профессия 12/119] ✓ пункт (5 разд., habr.com)
84s, осталось ~9 мин`.

## Выходные данные

| Артефакт | Путь | В git |
|---|---|---|
| Кластер разборов | `src/methodology/v1/guides/content/it.json` | да |
| Прогон и отчёты | `data/guides/<run>/<profession>/guides.json`, `report.md`, `summary.md` | нет |
| Кеш поиска/страниц/LLM | `data/guides/.cache` | нет |
| Аудит | `data/guides/audit-<date>/report.md`, `audit.json` | нет |
| Публикация | `apps/web/src/content/generated/guides.json` (после `release:build`) | да |

## Планка качества

- Структура и язык — валидатор (`npm run test`, тесты `tests/guides.test.ts`).
- Привязка к источнику — `npm run guides:audit`: числа, латинские термины и значимые слова
  разбора, которые есть в тексте источника. Медиана должна быть **≥ 0.8**; пункты **< 0.6** —
  на вычитку, **0.6–0.8** — «наблюдать».
- `no_data` — не брак: честный отказ, если источник не дал трёх содержательных разделов.
- Выборочная человеческая вычитка ~20% разборов остаётся обязательной: аудит ловит дрейф темы,
  но не смысловые ошибки внутри темы.

## Регламент

1. Не редактировать кластер и `generated/guides.json` руками: единственный путь — прогон агента;
   человек может поменять `review.status` на `reviewed`, когда прочитал разбор.
2. Менять промпт (`GUIDE_SYSTEM`, `PROMPT_VERSION`) только после калибровки на 10 пунктах и
   сравнения с текущим качеством; старые разборы перегенерировать через `--all`.
3. После прогона: `npm run typecheck`, `npm run test`, `npm run release:build:draft` (синхронизирует
   `generated/guides.json`), при отгрузке — `release:validate` / `release:build`.
4. Brave — платный: сначала `--limit 2` для проверки ключа и качества, полный прогон — только
   после подтверждения, что остаток средств достаточен. Не удалять `data/guides/.cache` без нужды:
   кеш экономит и Brave, и токены.
5. Кластер растёт линейно (~7 КБ на пункт, 763 пункта ≈ 5 МБ): следить за размером публикации,
   при необходимости отдавать разборы лениво (предложение в `COS-EAR-017` §6).
