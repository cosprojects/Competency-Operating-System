# COS-010 — Стандарт документации

## 1. Назначение

Документ задаёт единый формат внутренней документации, чтобы правки в одном месте не расходились с остальными. Состояние на момент проверки 15.10.2026: из 96 документов frontmatter был у 23, имена файлов велись в четырёх стилях, статусы — в четырёх форматах, шесть ссылок вели на несуществующие id.

Стандарт распространяется на всё в `docs/`. Он не касается кода и методических данных (`prisma/`, `src/`), у них свои контракты.

## 2. Frontmatter

Каждый документ начинается с YAML-блока:

```yaml
---
id: COS-RES-008
title: Короткое человеческое название
version: 1.1.0
status: Draft
owner: Research Team
last_updated: 2026-10-15
references:
  - COS-005
  - COS-ADE-110
---
```

| Поле | Обязательно | Правило |
|---|---|---|
| `id` | да | стабильный, не меняется при переименовании файла |
| `title` | да | без номера документа: номер живёт в `id` |
| `version` | да | `MAJOR.MINOR.PATCH` по разделу 6 |
| `status` | да | одно значение из раздела 5 |
| `owner` | да | роль, не имя человека: `Product Team`, `Research Team`, `Architecture Team` |
| `last_updated` | да | дата последней **значимой** правки, формат `ГГГГ-ММ-ДД` |
| `references` | нет | только id, каждый обязан существовать |
| `superseded_by` | при замещении | id документа, который заменил этот |

## 3. Идентификаторы

`COS-<ОБЛАСТЬ>-<НОМЕР>`, номер трёхзначный и не переиспользуется: удалённый id не отдаётся новому документу.

| Префикс | Область | Папка |
|---|---|---|
| `COS-0NN` | Foundation | `00-foundation` |
| `COS-DDD-NNN` | Доменная модель | `01-ddd` |
| `COS-ARCH-NNN` | Архитектура | `02-architecture` |
| `COS-ADE-NNN` | Adaptive Development Engine | `03-adaptive-development-engine` |
| `COS-EAR-NNN` | Experience Architecture | `04-experience-architecture` |
| `COS-BUS-NNN` | Business Architecture | `05-business-architecture` |
| `COS-COM-NNN` | Communication | `06-communication` |
| `COS-WEB-NNN`, `COS-DOC-NNN` | Сайт и публичные материалы | `07-website` |
| `COS-BP-NNN` | Бизнес-план | `08-business-plan` |
| `COS-RES-NNN` | Исследование | `09-research` |
| `COS-LEG-NNN` | Юридические документы и политики | `10-legal` |
| `COS-SCN-NNN` | Пользовательские сценарии (JTBD, CJM, тексты) | `11-scenarios` |

Отдельные серии без папки: `COS-<AREA>-<NNN>` в ссылках указывается всегда, даже если документ лежит не в своей папке.

## 4. Имена файлов

`COS-<ОБЛАСТЬ>-<НОМЕР>-<Название>.md`, слова через дефис, пробелов нет.

- Правильно: `COS-ADE-110-Competency-State-Model.md`
- Неправильно: `COS-ADE-110-Competency-State-Model.md.md`, `COS-BUS-010 Financial Model.md`, `COS-DDD-010-Cross-context Relationships copy.md`

Запрещено: двойное расширение `.md.md`, слово `copy` в имени, двойная точка, пробелы, документы в корне `docs/` вне своей папки.

**Легаси-исключение.** Файлы `00-foundation/01…09-*.md` сохраняют короткие имена до отдельного механического прохода; их `id` (`COS-001`…`COS-009`) уже соответствуют стандарту и в ссылках используются как обычно. Новые документы создаются только по правилу выше.

## 5. Статусы

Одна шкала, одно значение:

| Статус | Значение |
|---|---|
| `Draft` | рабочий текст, на него нельзя ссылаться как на решение |
| `In Review` | отправлен на ревью, содержание не меняется до заключения |
| `Approved` | решение зафиксировано, изменения — только новой версией |
| `Superseded` | заменён другим документом, обязателен `superseded_by` |
| `Retired` | выведен из работы без замены |

Уточнения пишутся в текст документа, а не в поле статуса: `status: Draft`, а не `Draft — гипотеза, требующая валидации`. Различия вида «Draft — переписан 08.10» переносятся в раздел «История изменений».

## 6. Версии

`MAJOR` — изменилось решение или вывод, на который ссылаются другие документы. `MINOR` — добавлен раздел или существенно расширено содержание. `PATCH` — правки формулировок, ссылок, оформления.

При смене `MAJOR` документ, на который ссылались, обязан получить запись в «Истории изменений» с указанием, что именно поменялось.

## 7. Ссылки

- На документы — по `id` в бэктиках: `` `COS-RES-005` ``. Ссылка на имя файла запрещена: имя может измениться.
- На код и данные — по пути в бэктиках: `` `prisma/schema.prisma` ``.
- На внешний источник — полной ссылкой, с указанием типа доказательства по `COS-RES-001` при числовых утверждениях.
- Каждый id в `references` и в тексте обязан существовать. Проверяется скриптом (раздел 9).

## 8. Структура и замещение

Новый документ кладётся в папку своей области. Если тема не подходит ни одной — заводится обсуждение о новой папке, а не документ в корне.

Замещение: старый документ получает `status: Superseded` и `superseded_by: <id>`, в начале текста — строка «Заменён на `COS-...` », сам текст не удаляется. Пример на 15.10.2026: контур из трёх веток снят решением A в `COS-RES-008` (§1.1), а `COS-RES-002`, `COS-RES-003` и `COS-RES-007` подлежат пометке.

## 9. Машинные проверки

Стандарт проверяем автоматически. Скрипт проверяет:

1. наличие обязательных полей frontmatter;
2. `status` из допустимого набора;
3. каждый id из `references` и из текста существует;
4. имена файлов по разделу 4 (включая легаси-исключение);
5. отсутствие дублей `id`;
6. наличие `superseded_by` при `status: Superseded`.

Проверка запускается перед коммитом документации. Пока скрипта нет — проверка идёт вручную по этому списку.

## 10. Чек-лист нового документа

1. Определить область и свободный id.
2. Заполнить frontmatter целиком, `status: Draft`.
3. Написать назначение: на какой вопрос отвечает документ и для кого он.
4. Сослаться только на существующие id.
5. Проверить имя файла по разделу 4.
6. При замещении существующего — проставить `Superseded` и `superseded_by` у старого.

## 11. Приведение текущего состояния

Порядок работ по приведению документации к стандарту:

1. Добавить frontmatter 73 документам без него — по мере содержательной правки, а не отдельным проходом.
2. Пометить `Superseded` документы, снятые решением A в `COS-RES-008`.
3. Механический проход по именам: `.md.md`, `copy`, двойная точка, пробелы, два документа в корне.
4. **Выполнено 15.10.2026:** закрыты ссылки на несуществующие id — `id: COS-004` присвоен документу `04-company-narrative`, список «Used by» в `COS-WEB-000` переведён на существующие документы сайта.
5. Ввести проверку из раздела 9 в CI.

Пункты 1, 2 — содержательные и делаются вместе с правкой соответствующих документов. Пункт 3 — механический, выполняется одним проходом с проверкой ссылок после.
