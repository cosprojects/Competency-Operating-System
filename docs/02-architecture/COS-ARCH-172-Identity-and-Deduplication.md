# COS-ARCH-172 — идентичность и запрет дублей

## 0. Проблема

При масштабе главный риск — не плохой материал, а **дубли**: один курс под пятью
адресами с utm-метками, одна компетенция в двух профессиях, повторная привязка
того же материала на следующем прогоне. Дубли ломают аналитику, раздувают базу
и обесценивают рекомендации: пользователь видит один и тот же ресурс трижды.

Дубль нельзя ловить сравнением строк: `http://www.habr.com/a/?utm_source=x` и
`https://habr.com/a` — один ресурс, а «Курс по дизайну» и «Курс по дизайну мышления» —
разные.

## 1. Три уровня идентичности

| Уровень | Ключ | Что ловит | Ложные срабатывания |
|---|---|---|---|
| 1. Каноническая ссылка | нормализованный URL | точный дубль | нет |
| 2. Домен + заголовок | host + Жаккар по словам ≥ 0.85 | тот же ресурс по другому адресу | редко (однотипные страницы) |
| 3. Провайдер + заголовок | провайдер + ≥ 0.92 | перезалив того же курса | возможны, поэтому порог выше |
| 4. Узел онтологии | тип + нормализованный заголовок / алиасы | один термин двумя id | см. §4 |

### Каноникализация URL

- `http` → `https`;
- `www.` убирается, домен в нижнем регистре;
- удаляются utm-метки, `ref`, `source`, `fbclid`, `gclid`, `yclid`;
- фрагмент (`#…`) отбрасывается;
- хвостовой слэш убирается.

ID материала детерминирован: `material_<sha1(canonicalUrl)[:12]>`. Один ресурс —
один id, независимо от прогона.

## 2. Дедупликация потока

`dedupeResources(candidates, existing)` сравнивает кандидатов **и с уже существующими,
и внутри пачки**. Возвращает `{unique, duplicates}` с типом совпадения и похожестью —
это попадает в отчёт, а не молча отбрасывается.

## 3. Дедупликация связей

Даже уникальный материал не должен привязываться к компетенции дважды.
Проверяются связи каталога (`material.links`) и реестр привязанных материалов.

Реестр `data/workflow/attached-materials.json` — временное решение: он позволяет
повторному прогону увидеть материалы прошлых запусков. В итерации 2 переезжает в БД.

## 4. Дедупликация узлов онтологии

Дубли делятся на два класса:

| Scope | Пример | Что делать |
|---|---|---|
| `same_parent` | «Git» дважды под одной компетенцией | **ошибка**, узлы нужно слить |
| `cross_parent` | «Git» под `aidesigner-technical-literacy` и `aidesigner-ai-development` | решить: переиспользование или дубль |

`same_parent` — жёсткая ошибка сборки. `cross_parent` автоматически **не мержится**:
это может быть законное переиспользование термина в разных контекстах.

### Найденная модельная проблема и её решение

На снимке 809 узлов было найдено **8 пар дублей**: «Git», «MCP», «API», «Tool calling»,
«3D-моделирование», «Гипотезы», «Композитинг», «Структура промпта». Причина была не в
данных, а в модели: у узла был **один** `parentId`, поэтому знание, используемое в двух
компетенциях, вынужденно копировалось. При этом в каталоге 40 тегов уже имели несколько
связей — адаптер просто брал первую и терял 69 связей.

Решение (ADR-019): знания и навыки — **глобальные узлы**, членство выражается рёбрами
`part_of` (many-to-many). Узлы с совпадающими типом, названием и определением сливаются
автоматически; слабые дубли (название совпало, определения разные) только репортятся.

Результат на том же снимке:

| Показатель | Было | Стало |
|---|---|---|
| Узлов | 809 | 805 |
| Рёбер | 691 | 1 418 (из них `part_of` — 727) |
| Узлов в 2+ компетенциях | 0 (терялось) | 44 |
| Сильных дублей | 8 пар | 0 |
| Слабых дублей | — | 4 пары (на решение методиста) |

Слабые дубли — это, например, «Гипотезы» с определениями «Формулировка и проверка гипотез»
и «Формулировка проверяемых предположений о пользователе и продукте»: один и тот же
смысл разными словами. Автоматически не мержатся.

## 5. Интеграция в конвейер

| Стадия | Что делает с дублями |
|---|---|
| `research.collect` | отдаёт материалы с каноническим URL |
| `review.materials` | политика не зависит от дублей, но публикует только `auto_reject` скрытыми |
| `materials.attach` | три уровня дедупа + реестр привязок + детерминированный id |
| `release.publish` | считает дубли узлов и пишет их в статистику релиза |

Проверено двумя прогонами подряд:

```
прогон 1: linked 25 · newMaterials 25 · duplicates 0
прогон 2: linked  0 · newMaterials  0 · duplicates 50
          (25 exact_url + 25 link_exists)
```

То есть повторный прогон не добавил ни одного материала и ни одной связи.

## 6. Ограничения

- Состояние перенесено в БД (COS-ARCH-174): `Material.canonicalUrl` и
  `MaterialLink(materialId, nodeId)` уникальны — гонка закрыта на уровне схемы.
  Файловый реестр остался адаптером для локальных прогонов.
- Каталог (`catalog/it.json`) не перезаписывается: привязки не попадают в модель
  до отдельного шага публикации.
- Политика слияния `cross_parent` дублей не реализована — только отчёт.
