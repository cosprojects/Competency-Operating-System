# COS-ARCH-175 — публикация релиза и промоушен в продукт

## 0. Проблема

До этого шага конвейер заканчивался артефактом прогона: `release.publish` собирал снимок
онтологии, считал хэш и складывал его в `data/workflow/artifacts/`. Продукт при этом не
менялся — между «прогон succeeded» и «пользователь увидел» ничего не было.

## 1. Решение

Появился иммутабельный артефакт публикации и отдельный шаг промоушена.

```
release.publish (стадия конвейера)
   └─ release/publications/<releaseId>.json   — релиз: снимок, хэш, статистика, версия политики
      release/publications/index.json          — список релизов
      release/publications/current.json       — указатель на действующий релиз

release:promote (явный шаг в продукт)
   ├─ гейт: манифест status=ready + evaluateRelease
   ├─ buildPublicContent → публичный JSON для веба
   ├─ штамп publication{releaseId, snapshotHash, publishedAt, promotedAt} в контент
   └─ отметка promotedAt в записи релиза
```

Ключевое: **публикация и промоушен разделены.** Прогон публикует релиз (это данные),
промоушен выводит его в продукт (это решение). Промоушен нельзя сделать случайно.

## 2. Иммутабельность

- Один `releaseId` — одно содержимое. Повторная публикация с другим `snapshotHash`
  отклоняется: нужен новый `releaseId`.
- Повторная публикация с тем же хэшем — no-op (идемпотентность прогона).
- Указатель `current.json` переключается только новой публикацией.

## 3. Промоушен

```bash
npm run release:promote -- --release beta-1 --dry-run   # проверка без записи
npm run release:promote -- --release beta-1             # в продукт
npm run release:promote -- --release beta-1 --allow-draft  # локальный preview
npm run release:publications                             # список и текущий указатель
```

Гейт тот же, что у `release:build`: `status=ready` и `evaluateRelease().totals.passed`.
Без него промоушен останавливается.

## 4. Проверено на локальном контуре

```
конвейер (it.uxui, release beta-1): succeeded
publication: release/publications/beta-1.json · hash f713633c… · created true

release:publications:
  текущая публикация: beta-1 · f713633c0d0d · 2026-11-04T16:05
  промоушен: 2026-11-04T16:06

apps/web/src/content/generated/beta-1.json:
  publication{releaseId, snapshotHash, publishedAt, promotedAt, policyVersion}
  профессий 12 · размер 4.33 МБ
```

## 5. Что это даёт

- **Ответ на вопрос «что сейчас в проде»** — один указатель и хэш.
- **Аудит**: по `releaseId` видно снимок онтологии, статистику и версию политики.
- **Откат промоушена** — повторный `release:promote --release <предыдущий>`.
- **Идемпотентность**: повторный прогон не создаёт вторую публикацию.

## 6. Ограничения

- Публикационный снимок (онтология: узлы и рёбра) и веб-контент собираются **из одних
  и тех же исходников, но разными путями**: `release.publish` фиксирует снимок,
  `release:promote` пересобирает контент из модели. Связь подтверждается хэшем снимка
  в контенте, но контент не строится из снимка. Полная гарантия — следующий шаг:
  веб-сборка должна читать снимок публикации, а не модель.
- Файлы публикаций не коммитятся (`.gitignore`): в проде их место — объектное хранилище.
- Откат промоушена не откатывает модель данных: если модель менялась, нужен git checkout
  соответствующего коммита. Указатель даёт только «какой релиз считать действующим».

## 7. Дальше

1. Веб-сборка из снимка публикации (единый источник: снимок → контент).
2. Хранение публикаций в объектном хранилище + подпись.
3. Промоушен по кнопке из админки с ролью «релиз-менеджер».
