# COS-EAR-016 — Система движения

## 1. Назначение и границы

Документ фиксирует, **как интерфейс COS движется**: какие приёмы разрешены, какие
значения токенов используются, где движение применяется и чем оно проверяется.

Опирается на уже принятый язык: `COS-COM-006` (§7 «Спокойная сложность»,
«Живая структура», «Осмысленная видимость», §8 «Пространство — носитель
смысла»), `COS-COM-007` (§4 отзывчивость и «естественное взаимодействие»,
§5 motion principles) и `COS-COM-011 §2.5` (ease-out, появление карточки 0.6 s,
рост нити 0.8–1.2 s, запрет overshoot/bounce/spring, запрет частиц и свечения).

Новые правила этот документ не изобретает. Он переводит их в конкретные
значения, имена токенов и код, чтобы движение можно было проверить, а не
обсуждать на вкус.

**Не описывает:** видео и AV-пайплайн (`COS-COM-011`), дизайн-систему компонентов
(`COS-COM-007`), раскладку и информационную архитектуру (`COS-EAR-004`,
`COS-EAR-008`).

## 2. Принципы

1. **Движение объясняет изменение.** Каждая анимация отвечает хотя бы на один
   вопрос из `COS-COM-007 §5`: что изменилось, почему, что делать дальше.
   Анимация без ответа не добавляется.
2. **Сила отклика пропорциональна значимости.** Наведение — 140 мс и 1–2 px;
   смена вида графа — 280 мс; появление секции — 560 мс со стаггером.
3. **Слои отражают смысл.** То, что ближе к зрителю, сильнее реагирует на
   курсор; бумага-канвас уходит медленнее всех. Это пространственная метафора
   `COS-COM-006 §8`, а не декор.
4. **Спокойно, без аттракциона.** Нет overshoot, bounce, spring, частиц,
   свечения, «дыхания», scroll-jacking и кастомного курсора. Единственное
   исключение — микро-отскок звёздочки сохранения (1.12, 240 мс) как фидбек
   действия.
5. **Доступность не опция.** `prefers-reduced-motion: reduce` отключает
   движение полностью — и в CSS, и в JS (rAF-циклы не запускаются).
6. **Ничего не прячем без JS.** Стартовое состояние скрытия ставит JS; без
   скриптов и до гидрации контент виден.

## 3. Глубина и параллакс

**Параллакс есть только у бумаги-канваса.** Курсор пишет в `<html>` две
переменные `--pointer-nx`, `--pointer-ny` (−1…1 от центра окна), а
`.paper-layer` сдвигается через `calc()` на ≤ 6 px в противоположную сторону.
Карточки и панели за курсором **не следят**: слежение за курсором у секций
оказалось шумом и убрано (раньше существовал атрибут `data-depth` — удалён
вместе с токенами глубины). Ощущение «элементы над канвасом» создаётся тем, что
бумага уходит, а карточки стоят.

Правила:

- параллакс только на **точном указателе** (`(hover: hover) and (pointer: fine)`);
  на тач-устройствах его нет;
- **интерактивный граф не двигается** под курсором: у узлов есть только
  собственный магнит (ниже), попадание мышью не страдает;
- следование — экспоненциальное сглаживание (`τ = 0.09 s`), без отскока;
  при уходе курсора переменная возвращается в ноль.

**Магнит карточек схемы.** Внутри канваса профессии карточки в радиусе 220 px
от курсора слегка тянутся к нему (до 8 px на экране) и доворачиваются к нему
(до 4°, `perspective(600px)`): ближний край «поднимается». Радиус и значения
затухают линейно, без отскока. Узлы не двигаются вместе со сценой — только
собственная реакция на курсор, поэтому попадание мышью не страдает. При уходе
курсора карточка возвращается на свою ось за 180 ms.

## 4. Токены

| Токен | Значение | Где |
|---|---|---|
| `--dur-75` | 75 ms | нажатие |
| `--dur-140` | 140 ms | наведение, микро-фидбек |
| `--dur-200` | 200 ms | вход модалки, полоса тоста |
| `--dur-280` | 280 ms | перелёт вида графа, баннер согласия |
| `--dur-560` | 560 ms | появление секции, рост нити |
| `--ease-out-soft` | `cubic-bezier(0.22, 0.61, 0.36, 1)` | вход, наведение |
| `--ease-out-structure` | `cubic-bezier(0.33, 1, 0.68, 1)` | рост нити, перелёт вида |
| `--ease-in-exit` | `cubic-bezier(0.4, 0, 1, 1)` | выход тоста |
| `--parallax-max` | 6 px | потолок параллакса |

Значения живут в двух местах и обязаны совпадать: CSS-блок «Движение и глубина»
в `apps/web/src/app/globals.css` и `apps/web/src/lib/motion/tokens.ts`
(там же — `PARALLAX_MAX_PX`, `GRAPH_VIEW_MS`, `EDGE_DRAW_MAX`).

## 5. Где что применяется

| Место | Движение | Атрибут / класс |
|---|---|---|
| Бумага-канвас | сдвиг за курсором ≤ 6 px | `.paper-layer` |
| Главная: hero, панели, лог | появление со стаггером | `data-enter` |
| Главная: секции ниже экрана | появление при прокрутке | `data-reveal` |
| `/professions`: плитки | волна 60 ms по порядку сетки (слева направо, сверху вниз), потолок 720 ms | `data-enter` + inline `animation-delay` |
| Полоса покрытия | рост слева направо | `.coverage-bar span` |
| Канвас: сборка схемы | карточки съезжаются из сжатого облака (14 % к центру, ≤ 46 px) и проявляются волной 16 ms, 380 ms каждая | `.graph-node.is-entering` |
| Канвас: магнит | карточки тянутся к курсору ≤ 8 px и наклоняются ≤ 4° | `--magnet-*`, `--tilt-*` |
| Канвас: нити | рост от начала к концу (`pathLength=1`), старт через 180 ms после карточек, стаггер 12 ms | `.graph-edge.is-drawing` |
| Канвас: вид | плавный перелёт фокуса и смены режима за 280 ms | `animateViewTo` |
| Канвас: панорамирование | запись трансформа в rAF, без ре-рендера на каждый `pointermove` | — |
| Узел графа | магнит: смещение и наклон к курсору | `.graph-node` transform |
| Панель компетенции | въезд справа на каждый новый выбор (`key` по компетенции) | `detail-in` |
| Сохранение | микро-отскок звёздочки | `.icon-button.is-popping` |
| Тост | вход 200 ms, выход 140 ms, полоса времени | `data-state`, `.toast-progress` |
| Модалки | общий вход 200 ms | `.modal-backdrop > *` |
| Баннер согласия | подъём снизу 280 ms | `.consent-banner` |
| Рейл навигации | голубая плашка-ховер перетекает между пунктами (240 ms, задержка 70 ms), между меню и низом — перелёт 110 ms | `.rail-hover-pill`, `--pill-*` |
| Рейл навигации: свёртывание | ширина 200 ↔ 84 px, отступы пунктов и обрезка лого/подписей — 280 ms; подписи при развороте появляются с задержкой 90 ms | `.nav-rail.is-mini` |

**Секвенция открытия профессии.** При обычном входе в профессию (не по прямой
ссылке на компетенцию) сначала появляется левый рейл и собирается схема —
правая панель при этом закрыта, иначе канвас сузился бы до появления схемы.
Через **1.5 с после первого кадра** схема фокусируется на первой компетенции
(перелёт 280 мс) и одновременно выезжает правая панель (`detail-in`, 260 мс).
Отсчёт идёт от `first-contentful-paint`, а не от гидрации: иначе на медленном
соединении пауза после видимого появления схемы растягивалась бы на время
загрузки JS. При `prefers-reduced-motion` паузы нет, на мобильных (`≤ 760 px`)
автопоказ отключён, а любой выбор компетенции до истечения паузы её отменяет.

**Границы панорамирования.** Каждый `pointermove` обновляет только позицию
трансформа в rAF; React-состояние меняется лишь при смене «идёт панорамирование»,
а проценты масштаба публикуются в тулбар не чаще раза в 90 мс. Это и есть
основной вклад в «отзывчивость» канваса.

## 6. Единственный выразительный акцент

Главные CTA главной страницы («Поделитесь своим мнением» в блоке-приглашении и
«Выбрать направление» в боковой панели) — компонент `PrimaryCta`. Идея Liquid
Carve Button сохранена: подсветка следует за курсором. Приведена к языку COS:

- нет goo-фильтра и вычитающей маски;
- нет spring и отскока;
- индиго вместо акцентного красного, радиус и кегль — как у `.button`;
- подсветка лежит **под подписью**, контраст текста не зависит от курсора;
- **тон подсветки выбирается по фактическому фону** (`applyTone` в
  `PrimaryCta.tsx`): на индиговой заливке — затемнение, на белой кнопке — лёгкая
  индиговая подсветка (≈10 % альфы), на прозрачной — самая слабая. Белый вариант
  нужен, чтобы эффект не затенял тёмную подпись;
- на тач-устройствах и при reduced motion подсветка не двигается.

Кнопка «Выбрать направление» на канвасе профессии **не** является акцентом: по
макету `247-35889` это вторичная белая кнопка. Акцент один и только для
действий, которые продвигают человека по продукту; вторая «эффектная» кнопка в
интерфейсе не появляется.

## 7. Отключение движения

`MotionProvider` ставит на `<html>` атрибут `data-motion="on|off"`:

- `off` — `prefers-reduced-motion: reduce`: трекер курсора не подписывается,
  бумага без сдвига, входные анимации отключены, нити сразу видны;
- CSS дополнительно гасит все длительности глобальным правилом из `globals.css`;
- перетекающая плашка рейла скрывается, вместо неё остаётся обычная заливка
  пункта при `:hover`;
- входные `data-enter` работают и без JS (чистый CSS), `data-reveal` без JS
  ничего не прячет.

## 8. Бюджет и ограничения производительности

- анимируются только `transform`, `translate` и `opacity`;
- `will-change` не ставится на `.graph-stage` и его предки: промоушен слоя
  заставляет Chrome масштабировать растровый кэш, текст «мылится» при зуме;
- один листенер `pointermove` на приложение, один `IntersectionObserver`;
- рисование нитей по одной отключается, если рёбер больше 60 (`.graph-edges.is-fading`);
- входные анимации используют `translate`, а не `transform`, чтобы
  `animation-fill-mode: both` не перебивал `:hover`;
- движение не блокирует ввод: клавиатурные сценарии ничего не ждут.

**Профиль затрат (замеры на production-сборке).**

| Решение | Зачем |
|---|---|
| Параллакс есть только у бумаги: карточки курсор не догоняют | слежение карточек за курсором — шум и лишний style recalc в кадре |
| Магнит: кэш рамки контейнера, только 8 ближайших карточек, квантование 0.15 px / 0.1° | `getBoundingClientRect()` в кадре заставлял браузер синхронно сбрасывать стили; лишние записи переменных не меняли картинку |
| `.graph-node` и карточки компетенций — `memo` со стабильными колбэками и рефами | наведение и выбор перерисовывают 1–2 карточки вместо десятков |
| `CompetencyGraph` — `memo` | проценты масштаба в тулбаре больше не перерисовывают схему |
| Тень рейла: `backdrop-filter: blur(6px)` вместо `blur(28px) saturate(150%)`, фон плотнее | рейл закреплён над прокручиваемым контентом: любой blur пересчитывается каждый кадр скролла |
| Фон модалки: `blur(3px)` вместо `blur(6px)` | полноэкранный blur — самая дорогая поверхность при открытом диалоге |
| `.profession-group:not(:first-child)` — `content-visibility: auto` | группы ниже экрана не раскладываются и не рисуются до подхода |
| Поисковый индекс — уникальные токены (`compactSearchText`) вместо полного текста | `/professions`: HTML 939 КБ → 407 КБ (−57 %), gzip 186 КБ → 112 КБ (−40 %); поиск идёт по словам в любом порядке |
| Шрифт Geist — `preload` | без него первый экран рисуется fallback-шрифтом и прыгает после swap |
| Корректировка схемы после загрузки шрифтов — мгновенная, без анимации | иначе 280-мс перелёт конкурировал бы с секвенцией открытия профессии |
| Фильтр списка — `useDeferredValue` | ввод не ждёт пересчёта списка |

Замеры: `Performance.getMetrics` и `longtask` на 1440×900 (DPR 1 и 2), сценарии
«скролл главной», «магнит по схеме», «реальный ховер 26 узлов», «выбор
компетенции». Во всех сценариях — 60 fps и ни одной задачи > 50 мс; при
искусственном замедлении CPU ×4 остаются длинные задачи от растеризации
2×-экрана, но JS в профиле занимает единицы процентов (магнит — ~3 мс на 2.5 с).
Это значит, что при реальных лагах смотреть нужно на dev-режим и GPU, а не на
React-рендеры.

## 9. Критерии приёмки

1. `prefers-reduced-motion: reduce`: нет параллакса, нет входных анимаций,
   весь контент виден, переходы вида мгновенные.
2. Параллакс ≤ 6 px, включается только при точном указателе.
3. Канвас: карточки входят волной (разные `animation-delay`), тянутся к курсору
   и возвращаются на ось после ухода курсора; выбор компетенции переводит вид
   плавно (≥ 5 кадров изменения трансформа), длинных задач > 150 мс нет.
4. Ни одна цель `data-reveal` не остаётся скрытой после прокрутки (есть страховка
   6 с на случай сбоя наблюдателя).
5. На 360 px нет горизонтального скролла; ошибок консоли нет.
6. `npm run typecheck`, `npm run test`, `npm run web:typecheck` — зелёные.

## 10. Проверка

```sh
npm run web:dev -- -p 3100            # отдельный терминал
npm run qa:motion                     # 22 браузерные проверки, отчёт в /tmp/axiona-motion
npm run qa:browser -- --base http://127.0.0.1:3100
npm run figma:compare -- --url http://127.0.0.1:3100/professions/uxui \
  --selector ".profession-summary" --design <png> --out /tmp/parity-after
```

`qa:motion` — `scripts/web/motion-check.mjs`, без зависимостей: сам поднимает
headless Chrome, проверяет параллакс, возврат слоёв, появление секций, reduced
motion, плавность вида графа, панорамирование, мобильный перелив и консоль.

## 11. Антипаттерны

- анимировать раскладку (ширину, высоту, отступы) вместо трансформа;
- пульсация, «дыхание», блики, частицы, plexus — прямо запрещены `COS-COM-011 §2.7`;
- анимация фильтра размытия на больших областях;
- появление контента только после JS;
- бесконечные автоанимации дольше 5 с (WCAG 2.2.2);
- движение, которое прячет состояние: элемент уже переключился, а выглядит
  переключающимся.
