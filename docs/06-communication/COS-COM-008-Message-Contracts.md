# COS-COM-008 — Контракты сообщений для генерации

## 1. Назначение и разделение

Содержательные сообщения пишет подключённая модель (DeepSeek API). Сценарии не содержат скриптов: они задают, **что сообщение обязано донести, чего не должно, сколько может занимать и какие данные получает модель**. Формулировки создаются в момент показа.

Разделение текста:

| Тип | Кто пишет | Примеры |
|---|---|---|
| **Статичные подписи** | Автор, слой локализации | названия кнопок, подписи полей, заголовки шагов, тексты ошибок валидации |
| **Содержательные сообщения** | Модель по контракту | объяснение хода разбора, подтверждение фактов, ответ по компетенции, частичный результат, рекомендации |

Причина разделения: подпись кнопки должна быть неизменной и проверяемой, а объяснение результата зависит от данных конкретного человека. Генерировать «Отправить» бессмысленно и рискованно.

## 2. Общие правила

**Обязательно в любом сообщении:**

1. Опираться только на данные, переданные в контексте. Не добавлять факты, которых нет.
2. Называть основание вывода: какая самооценка, какой материал или какой ответ на кейс к нему привели.
3. Заканчивать следующим шагом, если сообщение завершает этап.
4. Писать на «вы», короткими фразами, без канцелярита.

**Запрещено:**

- Обещания трудоустройства, дохода, повышения, точности прогноза.
- Утверждения о «научной валидированности» и любые заявления о доказанной точности.
- Оценки личности, интеллекта, эмоционального состояния.
- Ярлыки: «вы аналитик», «вам подходит профессия X».
- Подсказки по содержанию кейса до его оценки.
- Выдуманные числа: проценты, счётчики, «тысячи пользователей».
- Давление: обратный отсчёт, «только сейчас», «последний шанс».

**Тон.** По `COS-COM-001`. Ошибка говорит, что произошло и что делать. Похвала конкретная, без восторженности.

**Длина.** Сообщение шага — до 3 предложений. Рекомендация — до 5 пунктов, каждый до 2 предложений. Если данных больше, она разбивается на части.

## 3. Каталог сообщений

| ID | Когда возникает | Этап |
|---|---|---|
| M1 | Начало разбора материалов | обработка |
| M2 | Найдены факты в материалах | обработка |
| M3 | Материалов нет или фактов не нашлось | обработка |
| M4 | Ответ по выбранной компетенции | вопросы |
| M5 | Вопрос вне темы | вопросы |
| M6 | Просьба подсказать решение кейса | кейс |
| M7 | Частичный результат до регистрации | результат |
| M8 | Рекомендация по цели | результат |
| M9 | Объяснение расхождения самооценки и практики | результат |
| M10 | Недостаточно данных для вывода | результат |
| M11 | Сбой обработки | любой |

### M1. Начало разбора

**Обязано:** сказать, что именно читаем (файлы, ссылки), и что произойдёт дальше.
**Не должно:** обещать срок, оценивать материалы.
**Лимит:** 2 предложения.
**Данные:** число файлов, число ссылок, наличие текста.

### M2. Найдены факты

**Обязано:** перечислить найденное как проверяемые утверждения, а не как выводы о человеке; показать, откуда взят каждый факт; попросить подтвердить.
**Не должно:** называть уровень, делать выводы о пригодности, объединять факты в «профиль».
**Лимит:** до 5 фактов, каждый до 15 слов.
**Данные:** факты с фрагментами-основаниями, узлы.

### M3. Материалов нет

**Обязано:** сказать, что это не проблема; предложить один вопрос о прошлом опыте; объяснить, что дальше будет кейс.
**Не должно:** штрафовать, снижать оценку словами, требовать материалы.
**Лимит:** 3 предложения.
**Данные:** выбранный трек, уровень.

### M4. Ответ по компетенции

**Обязано:** отвечать по существу выбранной компетенции; связывать с уровнем и тем, что подтверждено.
**Не должно:** давать общие советы по профессии; подсказывать решение кейса; выходить за тему.
**Лимит:** 3 предложения.
**Данные:** узел, его описание, якоря L0–L3, подтверждённый уровень, остаток вопросов.

### M5. Вопрос вне темы

**Обязано:** коротко объяснить назначение сервиса.
**Не должно:** пересказывать правила фильтра, читать нотации, предлагать «спросить иначе».
**Лимит:** 1–2 предложения.

### M6. Просьба подсказать решение кейса

**Обязано:** отказать и объяснить, почему это обесценивает проверку; указать, что разбор будет в результате.
**Не должно:** намекать на количество пунктов, называть пропущенное, хвалить за «правильный вопрос».
**Лимит:** 2 предложения.

### M7. Частичный результат

**Обязано:** назвать 1–2 подтверждённые сильные стороны и одну зону роста — с уровнями; сказать, что остальное откроется после подтверждения адреса; объяснить, зачем адрес.
**Не должно:** показывать скрытые значения; давить; обещать «полную картину личности».
**Лимит:** 4 предложения.
**Данные:** раскрытые узлы и уровни, число скрытых.

### M8. Рекомендация по цели

Контракт зависит от цели, выбранной на первом шаге.

| Цель | Обязано содержать | Данные |
|---|---|---|
| Сменить направление | что переносится в целевое и почему; что добрать | узлы с весами переноса, целевой трек |
| Повысить грейд | что уже соответствует следующему уровню; что отстаёт | уровни узлов, требования следующего |
| Подтянуть слабые стороны | приоритетный список узлов с разрывом и основание приоритета | `calibrationDelta`, подтверждения |

**Не должно:** перечислять курсы и уроки; строить «карту развития»; обещать срок до уровня.
**Лимит:** до 5 пунктов.

### M9. Объяснение расхождения

**Обязано:** нейтрально назвать, где самооценка выше или ниже подтверждённого, и на основании чего.
**Не должно:** оценивать человека («переоцениваете себя»), сравнивать с другими.
**Лимит:** 2 предложения на узел.

### M10. Недостаточно данных

**Обязано:** сказать, чего не хватает и что даст вывод; предложить конкретное действие.
**Не должно:** выдавать общую рекомендацию «развивайтесь».
**Лимит:** 2 предложения.

### M11. Сбой обработки

**Обязано:** сказать, что не получилось, что сохранено и что делать.
**Не должно:** извиняться многократно, обвинять пользователя, показывать технические детали.
**Лимит:** 2 предложения.

## 4. Что модель получает на вход

| Данные | Обязательность | Источник |
|---|---|---|
| Шаг и его контракт (ID) | да | этот документ |
| Трек и цель | да | сессия |
| Уровень и подтверждения по узлам | да | `Competency State` |
| Фрагменты материалов и факты | если есть | `EvidenceRecord` |
| Остаток вопросов и лимиты | да | шлюз |
| Язык | да | локаль |

Модель не получает: email, идентификаторы пользователя, историю чужих сессий, полный профиль целиком.

## 5. Проверка сгенерированного сообщения

Сообщение принимается, если:

1. Соответствует контракту своего ID (обязательные элементы присутствуют).
2. Не содержит запрещённого из раздела 2.
3. Укладывается в лимит длины.
4. Не раскрывает критерии кейса до оценки.
5. Не содержит чисел, которых нет во входных данных.

Если проверка не прошла — сообщение не показывается; используется заготовка шага (статичная, авторская). Это же поведение при недоступности модели.

Устройство запроса к модели — слои, порядок для кэша, формат ответа — описано в `COS-COM-009`.

## 6. Что не генерируется

- Подписи кнопок, полей и шагов.
- Юридические тексты (`COS-LEG-001`, `COS-LEG-002`).
- Тексты кейсов и проверочных заданий: они приходят из методического пакета.
- Тексты ошибок валидации формы.
