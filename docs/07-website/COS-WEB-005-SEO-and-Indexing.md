# COS-WEB-005 — SEO и индексация

**Status:** Draft
**Owner:** Competency Operating System Team
**Stage:** Website & Release
**Version:** 1.1
**Дата:** 2026-11-23

> **1.1 (2026-11-23).** Добавлены чистые адреса компетенций: `/professions/[slug]/[competency]`,
> 308 со старых `?competency=` и `/competencies/[id]`, canonical на основную страницу для
> компетенций, которые входят в несколько профессий. Карта сайта — 176 канонических адресов.

---

# 1. Контур и домен

SEO-контур продукта — **`app.axiona.world`**. Это решение COS-REL-005 (ADR-025): продукт живёт на
поддомене, корпоративный сайт остаётся на `axiona.world` и не переносится до отдельного решения.

Причина: уникальный контент, который может ранжироваться, — карта профессий, компетенций и
материалов — находится в продукте. Корпоративный сайт — витрина из 16 страниц, её роль — объяснить
компанию и привести человека в продукт.

Следствия:

- `APP_URL` в окружении — **единственный** источник канонического домена. От него считаются
  `canonical`, `sitemap.xml`, `robots.txt` и `og:image`. Ошибка в `APP_URL` = ссылки на чужой домен.
- Корпоративный сайт `axiona.world` — отдельный репозиторий. Его проблемы (canonical указывает на
  apex, а apex отдаёт 308 на `www`; sitemap перечисляет редиректы) чинятся там, не здесь.

## 2.1. Компетенция в нескольких профессиях

Одна компетенция может входить в несколько профессий: 514 вхождений против 157 разных id.
Содержание (определение, знания, навыки, материалы) у неё одно, поэтому:

- канонический адрес компетенции — первое вхождение в модели (`lib/competency-routes.ts`);
- остальные вхождения открываются с картой своей профессии, но `canonical` указывает на основную
  страницу — иначе поисковик увидит сотни почти одинаковых документов;
- в `sitemap.xml` попадает только канонический адрес, поэтому 157 страниц, а не 514.

# 3. Как проверить

```sh
npm run typecheck && npm run test && npm run copy:check   # контракты проекта
npm run og:build                                          # пересобрать OG-картинку
cd apps/web && ../../node_modules/.bin/next build          # маршруты robots/sitemap собираются статически
```

На запущенном приложении:

```sh
curl -s https://app.axiona.world/robots.txt                     # Disallow /api/, /admin/ + Clean-param + Sitemap
curl -s https://app.axiona.world/sitemap.xml | grep -c "<loc>"   # 176; параметров быть не должно
curl -s https://app.axiona.world/professions/uxui | grep -o '<link rel="canonical"[^>]*>'
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" \
  "https://app.axiona.world/professions/uxui?competency=ui-color"   # 308 → /professions/uxui/ui-color
curl -s https://app.axiona.world/professions/uxui/ui-color | grep -o '<link rel="canonical"[^>]*>'
curl -s https://app.axiona.world/login | grep -o '<meta name="robots"[^>]*>'   # noindex, follow
```

Канонический адрес компетенции одинаков для всех её вхождений; старый адрес с параметром обязан
отвечать 308, а не 200.

## 3.1. Проверка после деплоя одной командой

```sh
npm run seo:verify -- --base https://app.axiona.world
```

Проверяет всё, что перечислено выше, на живом контуре: `robots.txt` (разрешения, `Clean-param`,
sitemap на своём домене), `sitemap.xml` (нет параметров, нет чужих доменов и дублей, есть страницы
компетенций), `canonical` на главной/направлениях/профессии/компетенции, постоянные редиректы со
старых адресов, `noindex` на служебных страницах, `og:image` (реально отдаётся), `twitter:card`,
JSON-LD (`Organization`, `CollectionPage`, `DefinedTerm`). Про верификацию панелей — строка `INFO`,
пока метатеги не заданы.

Код выхода 1 — есть проблемы, читать построчный вывод. На старой сборке команда показывает именно
те ошибки, которые исправляет P0: параметры в sitemap, отсутствие canonical и noindex, нет `og:image`.


# 4. Подключение панелей вебмастеров

Порядок один и тот же: подтвердить владение → отправить `sitemap.xml` → запросить переобход
главных страниц → смотреть отчёты об индексации.

## 4.1. Google Search Console

1. Открыть <https://search.google.com/search-console>, аккаунт Google владельца.
2. «Добавить ресурс» → **«Ресурс с префиксом»** → `https://app.axiona.world`.
   (Домен-ресурс `axiona.world` тоже полезен, но он покрывает корпоративный сайт.)
3. Подтверждение: способ «HTML-тег» — скопировать только значение `content` в
   `GOOGLE_SITE_VERIFICATION`. DNS-вариант (TXT) тоже работает, но требует доступа к DNS.
4. После перезапуска приложения: «Проверить». Метатег уже будет в `<head>` главной.
5. «Файлы Sitemap» → добавить `sitemap.xml`.
6. «Проверка URL» → `https://app.axiona.world/` → «Запросить индексирование». Повторить для
   `/professions` и 3–5 самых важных профессий.
7. Через 3–7 дней смотреть «Индексирование страниц»: сколько «Проиндексировано», сколько
   «Просканировано, но не проиндексировано», и «Альтернативная страница с корректным canonical» —
   последнее должно расти за счёт `?competency=`.

## 4.2. Яндекс.Вебмастер

1. Открыть <https://webmaster.yandex.ru>, войти аккаунтом Яндекса владельца.
2. «Добавить сайт» → `https://app.axiona.world`, регион — **Москва** (продукт на российском VDS).
3. Подтверждение: «Метатег» → значение в `YANDEX_SITE_VERIFICATION`. Можно и DNS, и HTML-файл.
4. «Индексирование → Файлы Sitemap» → `https://app.axiona.world/sitemap.xml`.
5. «Индексирование → Переобход страниц» → добавить главную и 3–5 профессий.
6. «Индексирование → Страницы в поиске»: смотреть «Исключённые страницы» и «Дубликаты».
   `Clean-param` в robots.txt должен снять часть дублей по `?competency=`.
7. «Диагностика»: устранить критичные ошибки, если появятся.

## 4.3. Bing Webmaster Tools

1. <https://www.bing.com/webmasters> → «Add site» → `https://app.axiona.world`.
2. Проще всего «Import from Google Search Console». Либо метатег → `BING_SITE_VERIFICATION`.
3. Отправить `sitemap.xml`. Bing отдаёт часть трафика и в некоторых регионах заметнее, чем Google.

## 4.4. Метрика

Яндекс.Метрика нужна не для позиций, а для сравнения: SEO-переходы, поведение, отказы. Ставить
счётчик — отдельная задача вместе с обновлением политики cookie (`COS-LEG-002`, `legal/cookies`):
нельзя ставить аналитику без отражения в политике.

# 5. Что нужно от владельца

| Что | Зачем | Кто делает |
|---|---|---|
| Аккаунт Google + права на `GOOGLE_SITE_VERIFICATION` | Search Console | владелец |
| Аккаунт Яндекса + права на `YANDEX_SITE_VERIFICATION` | Вебмастер, Метрика | владелец |
| Доступ к DNS `axiona.world` | DNS-подтверждение или TXT-записи, если метатег не подходит | владелец |
| Перезапуск контейнера с новыми env | метатеги верификации | владелец или деплой |

Пока панели не подтверждены, индексация не «жмётся»: Google узнает о сайте по sitemap и внешним
ссылкам, но без панели нет обратной связи и запроса переобхода.

# 6. Этапы

## 6.1. Сделано: чистые адреса компетенций (2026-11-23)

`?competency=` заменён на `/professions/[slug]/[competency]`: 157 канонических страниц вместо
фильтра, 308 со старых адресов, карточки компетенций в карте профессии стали настоящими ссылками
(краулер обходит 48 компетенций с каждой страницы профессии). Новые страницы отдают ~20 тыс.
знаков текста — заметно больше, чем страница профессии (~12 тыс.).

Попутно нашлась и починена ловушка каркаса: `AppShell` и `NavRail` определяли страницу карты
регуляркой `^/professions/[^/]+$` в двух местах. Новый двухсегментный маршрут в неё не попадал,
поэтому на странице компетенции рейл разворачивался, а схема сжималась с 436 до 208 px. Теперь
проверка одна — `isCanvasPath()` в `lib/routes.ts`.

## 6.2. Осталось

1. **Хлебные крошки + `BreadcrumbList`.** Разметку нельзя ставить без видимых крошек; сначала
   вёрстка, потом JSON-LD. На страницах компетенций крошки дают понятный путь «Направления →
   Профессия → Компетенция».
2. **FAQ на страницах профессий и компетенций.** Даёт `FAQPage` и закрывает частые вопросы;
   контент — из описаний и материалов, авторский текст согласовывать с владельцем.
3. **Кэш и скорость.** Публичные страницы сейчас `force-dynamic` с `Cache-Control: private,
   no-store`, TTFB 0,5–0,6 с, HTML страницы профессии ~500 КБ. Цель — отдать кэш на публичное
   и уменьшить RSC-payload.
4. **Контентный слой.** 5 МБ описаний знаний и навыков лежат в `/api/guide` под `Disallow: /api/`.
   Это готовый материал для индексируемых страниц — переиспользовать, а не писать заново.
5. **Бренд.** По запросу «axiona» выдаётся другая компания. Нужен бренд-хаб и разбор брендовых
   запросов; частично решается связкой корпоративный сайт → продукт.

# 7. Правила, чтобы не сломать

- Новую публичную страницу — только вместе с `alternates: canonical(...)` и записью в `sitemap.ts`.
- Служебную страницу — только с `NOINDEX_*` из `lib/seo.ts`.
- Компетенция в нескольких профессиях — canonical на основную страницу (`primaryCompetencyPath`),
  в sitemap только она одна. Не выводить повторные вхождения в карту сайта.
- Открывать компетенцию — только по пути, не параметром; параметр в адресе — повод добавить 308.
- Новый маршрут внутри `/professions/…` — добавить в `isCanvasPath()` (`lib/routes.ts`), иначе
  каркас посчитает его обычной страницей и сожмёт схему.
- `APP_URL` менять вместе с DNS и панелями; после смены — пересобрать (robots/sitemap статические).
- `?параметр` в sitemap не добавлять: параметризованные адреса канонизируются, а не индексируются.
- OG-картинку не править руками: `npm run og:build`.
