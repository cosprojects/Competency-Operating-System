# COS-RES-010 — Сбор требований профессии

## 1. Назначение

Документ фиксирует проход, который отвечает на вопрос «что требуется для профессии». Он не оценивает человека и не переписывает закрытый аудит уровней в `COS-RES-009`.

Результат прохода пока журнал свидетельств. Форма записей компетенции в `src/methodology/v1/design-competency-graph.json` не выбрана, поэтому граф этим проходом не меняется.

Две попытки другой сборки закрыты в `COS-RES-011` и правила этого документа не заменили.

## 2. Граница

Профессия задаёт требования и не владеет копией компетенции. Компетенция сбора — отдельная идентичность в доменной модели. Узел с картиной работы и якорями остаётся объектом аудита: сбор его не читает и не пишет.

Знание и навык — свои идентичности. Одна составляющая может быть связана с несколькими компетенциями, если источник прямо показывает обе принадлежности. Совпадение темы связь не создаёт.

`targetLevel`, самооценка, опыт, кейсы и доказательства в полноту сбора не входят. Завершённый проход означает, что принятые источники обработаны и нерешённое записано пробелом. Он не означает, что модель профессии полна.

## 3. Последовательность

1. Поиск источников.
2. Извлечение утверждений.
3. Определение роли утверждения.
4. Сопоставление идентичностей.
5. Установление связей.
6. Повторяемость и пробелы.
7. Повторный проход.

Шаги 1–2 выполняет `npm run collect:requirements`. Журнал свидетельств после этого не переписывается.

Шаги 3–5 для уже допущенных фрагментов выполняет отдельная команда `npm run match:identities`. Она читает журнал свидетельств и пишет журнал решений. Порог сходства не используется. Фрагмент без предмета работы и вида результата остаётся неразрешённым: идентичность и связь не создаются. Языковые версии одного поля `description` и название той же записи — одна идентичность, потому что это одна запись, а не потому что тексты похожи.

## 4. Поиск

Для профессии собираются запросы по шаблонам. Набор можно расширить, если материала мало. Шаблоны не словарь компетенций.

Русские шаблоны подставляют название из `src/methodology/v1/profession-catalog.json`:

- Ключевые навыки {профессия}
- Что должен уметь {профессия}
- Требования к специалисту {профессия}
- Профессиональные компетенции {профессия}
- Обязанности {профессия}

Английские шаблоны подставляют отдельно переданную английскую подпись. Без неё они не строятся и название не переводится догадкой:

- Essential skills {profession}
- Skills and competencies {profession}
- What does a {profession} do
- Required skills for a {profession}

Поиск широкий. Тип страницы решается после обнаружения, а не фильтром запроса.

## 5. Свидетельство

Страница из поиска — кандидат, пока у неё не записаны адрес и тип. Типы: справочник, вакансия, программа, отраслевой материал. Если тип не один или не узнан, страница остаётся кандидатом и её фрагменты в сопоставление не идут.

Утверждение с принятой страницы ещё не компетенция. У свидетельства есть способ получения, адрес, место в источнике и основание. Прямой `--url` не получает идентификатор запроса. Идентификатор запроса пишется только у страницы, которую открыл этот запрос.

Основание есть у описания навыка ESCO, у названия навыка в связях занятия и у раздела HTML про навыки, обязанности, требования или компетенции. Заголовок страницы таким разделом не считается. Фрагмент без основания остаётся в журнале и в сопоставление не идёт. Зарплата и общее определение профессии поэтому сохраняются и не становятся материалом идентичности.

## 6. Независимость

Один и тот же текст — одно свидетельство, сколько бы адресов его ни повторили. Повтор на том же сайте независимости не добавляет. Языковые версии одной записи ESCO остаются разными фрагментами и делят один идентификатор записи: это одно независимое свидетельство, а не число языков. Частота считается по таким записям. Она может выбрать, какую формулировку показывать у уже установленной идентичности. Сама по себе она идентичности не объединяет.

## 7. Где автомат останавливается

Код строит запросы, принимает переданные страницы, отсекает дословные копии и выписывает фрагмент с адресом. Создание идентичности, слияние и связь он не делает.

Дальше действует критерий, проверенный на парах и на повторном проходе user interface designer. Он ещё не подтверждён полным сбором профессии и в граф не переносится.

Два фрагмента — одна компетенция, когда из обоих виден один предмет работы и один вид результата. Условия, примеры и способ предмет не меняют. Общие слова, инструмент и отдельное действие совпадением не являются.

Разные предмет или результат — разные идентичности, даже при общей теме.

Фрагмент, который называет приём внутри предмета и своей области не задаёт, компетенцией не становится.

Если фрагменты не доказывают ни совпадение, ни различие, ни принадлежность составляющей, пишется пробел. Запись и связь не создаются.

«Работа с цветом» и «основы колористики» из-за общей темы не сливаются: первая может быть действием, вторая — знанием.

Связь составляющей с компетенцией ставится, только если источник показывает принадлежность. Две связи у одной составляющей возможны, когда один источник прямо относит её к двум областям. Такой подтверждающий фрагмент в проверенной выборке не встретился.

## 8. Повтор

Повтор того же прохода читает уже записанные фрагменты. Дословный повтор не создаёт вторую запись. Пробел закрывается только новым фрагментом, который даёт недостающее основание.

## 9. Что пишет код

Команда:

```bash
npm run collect:requirements -- --profession uxui --label "UX/UI designer" --url https://example.edu/program
```

Журнал пишется в `data/requirement-collection/<professionId>.json`. Поле `writesToGraph` всегда ложно. В журнале есть запросы, страницы с типом и статусом, фрагменты и число независимых свидетельств. Идентичностей компетенций в нём нет.

Без `--url` команда записывает только запросы и не подставляет источники сама.

Сопоставление:

```bash
npm run match:identities -- --profession uxui
```

Журнал решений пишется в `data/requirement-collection/<professionId>-identity.json`. У каждого решения есть фрагмент, адрес, место и запись источника. `writesToGraph` ложно. Входной журнал свидетельств эта команда не меняет.
