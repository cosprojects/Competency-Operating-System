# COS-RES-013 — Сборка профиля профессии из свидетельств ESCO

## 1. Назначение

Документ описывает сборку профиля профессии: целевое дерево компетенций, заполненное свидетельствами открытого источника. Дерево нужно, чтобы видеть, какие листья подтверждены, какие остались пробелом и какие навыки источника в дерево не входят.

Это не новый способ доказать компетенцию. Доказательством остаётся запись источника с описанием. Сборка организует выдачу для человека и не пишет граф.

## 2. Границы

- Профиль не меняет `src/methodology/v1/design-competency-graph.json` и не поднимает `methodologyVersion`.
- Уровни `L0–L3`, `targetLevel`, самооценка и оценка человека в профиль не входят.
- Сборка не утверждает полноту профессии. Лист без свидетельства — пробел, а не отсутствие компетенции.
- Инструмент не является компетенцией. Инструменты попадают в ветку `Design Tools` с видом `tool` и исключаются из диагностики графа.
- Универсальная база — листья со `scope: universal` (типографика, теория цвета, композиция). Они относятся ко всем дизайнерам, поэтому подтверждаются доменными занятиями (`art director`, `desktop publisher`) и отдельными записями ESCO, а не требованиями одной профессии. Привязка к конкретной профессии для них не требуется, но запись и её описание обязательны.
- Маппинг — организация выдачи, а не соответствие узлу графа. Сходство названий доказательством не считается.
- В профиль не попадают названия, придуманные моделью. Все названия — записи ESCO. LLM в этой версии не используется.

## 3. Входы

| Вход | Файл | Что задаёт |
|---|---|---|
| Целевая таксономия | `src/methodology/v1/profile/taxonomy/<profession>.json` | ветки, группы, листья и вид каждой цели |
| Маппинг | `src/methodology/v1/profile/mapping/<profession>.json` | занятия-источники, правила `название ESCO → цель`, причины отброса |
| Универсальная база | там же: `universalOccupations`, `universalSkills` | доменные занятия и записи ESCO для листьев `scope: universal` |
| Источник | ESCO API (`resource/occupation`, `resource/skill`), версия `v1.2.0` | записи навыков, их описания и связи с занятиями |
| Кеш | `data/profile/esco-cache/` | повторный прогон без сети; сбрасывается флагом `--refresh` |
| Диагностика | `design-competency-graph.json`, `profession-catalog.json` | текущий граф и открытые профессии |

Для UX/UI выбрано пять занятий ESCO: `user interface designer` и `user experience analyst` — ядро, `ICT usability tester`, `ICT accessibility tester`, `graphic designer` — поддержка. Для универсальной базы добавлены два доменных занятия: `art director` (design principles) и `desktop publisher` (typography). Одно занятие не покрывает и UI, и UX, а его optional-навыки содержат десятки языков программирования, поэтому источник задаётся набором, а не одной ссылкой.

## 4. Порядок сборки

1. Читаются занятия из маппинга, ссылки на навыки складываются в один список.
2. Навык дедуплицируется по записи ESCO: одна запись — одна строка, сколько бы занятий её ни назвали. Свидетельства занятий сохраняются.
3. Каждый навык проверяется по маппингу. Правило нашлось — навык идёт в дерево. Не нашлось — проверяются правила отброса с причиной. Не нашлось ни того, ни другого — навык пишется в «не сопоставлено».
4. Для сопоставленных навыков читается описание ESCO. Цитата сохраняется как есть.
5. Добавляются записи универсальной базы: правило `universalSkills` берёт запись из доменного занятия по названию или напрямую по `escoUri`; цель обязана быть листом `scope: universal`.
6. Строится дерево: лист `supported`, если у него есть хотя бы одна запись с описанием; иначе `no_evidence` и запись в пробелы. Записи уровня группы и ветки показываются отдельно. Универсальные листья помечаются `∞`.
7. Выполняется диагностика сопоставления с текущим графом методологом (`methodologist/decide.ts`). Это не запись требований.
8. Пишутся журнал профиля, человекочитаемое дерево и очередь на проверку.

## 5. Правила

- Правило маппинга обязано иметь `basis` — почему источник поддерживает именно эту цель.
- Правило, которому не нашлось названия в выбранных занятиях, попадает в `mappingMissing`. Это сигнал: источник выбран неверно или правило устарело.
- Причины отброса перечисляются по группам (`programming_language`, `software_engineering`, `project_management`, `other_domain_motion_3d`, `media_production`, `business_admin`, `legal_policy`, `data_ai_infra`, `transversal`). Молча ничего не отбрасывается.
- Навык с неясной целью остаётся в «не сопоставлено», а не приписывается ближайшей теме.
- Универсальная запись без описания источником не считается: лист остаётся пробелом, а запись попадает в очередь проверки.
- Одна запись ESCO — одно свидетельство. Одинаковые записи из профессии и универсальной базы не дублируются.
- Повторный прогон идемпотентен: ключ записи — профессия + запись ESCO + название, дубликатов не появляется.
- Стоимость прогона — запросы к открытому ESCO API; ключи и платные сервисы не нужны.

## 6. Что пишет код

```bash
npm run profile:build -- --profession uxui
npm run profile:build -- --profession uxui --refresh   # перечитать ESCO
npm run profile:build -- --profession uxui --no-cache  # без кеша
```

| Файл | Содержимое |
|---|---|
| `data/profile/<profession>.json` | полный журнал: источники, дерево, записи, отбросы, пробелы, диагностика |
| `data/profile/<profession>.md` | дерево для чтения человеком |
| `data/profile/<profession>-review.json` | записи, которым нужен человек: нет описания, неоднозначное соответствие, новый узел, пробелы |

Во всех файлах `writesToGraph: false`. Шаг встроен в `src/methodology/v1/pipeline.json` под id `profile-build`.

## 7. Снимок прогона UX/UI (2026-10-21)

| Показатель | Значение |
|---|---|
| Занятий-источников | 7 (5 профессий + 2 универсальных) |
| Уникальных записей ESCO | 193 профессиональных + 5 универсальных |
| Сопоставлено с деревом | 70 |
| Из них универсальная база | 5 |
| Вне области профиля | 127 |
| Не сопоставлено | 1 (`task algorithmisation`) |
| Листья: подтверждено / всего | 10 / 18 |
| Универсальная база: листья | 3 / 3 (Typography, Color theory, Layout & composition) |
| Профессиональные листья | 7 / 15 |
| Группы: есть свидетельства / всего | 6 / 6 |
| Диагностика графа | `needs_node` 55, `ambiguous` 6, `reject_tool` 9, `add_requirement` 0 |

Пробелы: Figma, FigJam, Framer, Grids, Personas, User Flows, Information Architecture, High-Fidelity. Универсальная база закрыта: типографика — записью `typography` (через `desktop publisher`), теория цвета — `design principles` (через `art director`) и `determine colour shades`, композиция — `develop visual elements` и `determine image composition`. Каждая запись имеет дословное описание ESCO.

Остальные пробелы — не дефект сборки: ESCO не связывает их с выбранными занятиями или не содержит записи. Они закрываются новым источником (O\*NET, профстандарты, ФГОС), а не дописыванием названий.

## 8. Что не входит и что дальше

- O\*NET: нужен бесплатный `ONET_API_KEY`; его `Skills`, `Knowledge`, `Technology Skills` закрывают часть визуальных и инструментальных пробелов.
- Профстандарты, ФГОС, отраслевые рамки: отдельные адаптеры; сканы — только для законно полученных PDF.
- Рыночные сигналы (вакансии) — отдельный контур; в нормативные требования не попадают.
- Уровни, кейсы и персональная оценка — после устойчивости модели.
- Приёмка метода на независимой размеченной выборке — по `COS-ARCH-002`; текущий прогон её не заменяет.

## 9. Проверка

`tests/profile.test.ts` проверяет: корректность таксономии и маппинга, дедупликацию одного навыка из двух занятий, сохранение цитаты, различение `supported` и `no_evidence`, объяснение отбросов, правило без источника, маркировку инструмента, отсутствие записи в граф и отрисовку дерева.
