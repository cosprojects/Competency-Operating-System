# COS-RES-028 — поиск и релевантность открытых учебных материалов

Аналитический разбор контура «открытые материалы для компетенций»: что сейчас реально работает,
где теряются курсы/статьи/видео и что менять, чтобы находить больше релевантных и полезных источников.
Документ продолжает `COS-RES-027` (отчёт-агрегатор) и не заменяет его: `COS-RES-027` фиксирует
*сколько* открытых источников есть, этот — *почему их мало и какие из них полезны*.
Решения 2026-11-03 и реализация описаны в [`COS-REL-009`](../12-release/COS-REL-009-Materials-Review-and-Confirmation.md).

## 1. Контекст и вопрос

Вопрос: как улучшить текущий модуль агрегации ссылок на материалы, чтобы в открытых источниках
находилось больше релевантных и полезных курсов, статей и видео по компетенциям профессий.

Границы анализа:

- контур обучения (не граф компетенций и не диагностика);
- источники, которые уже есть в репозитории: реестр `learning-sources`, Material Agent,
  связи «компетенция → источник», публикационный gate Beta 1 и раздел «Материалы» в вебе;
- без изменений кода: только разбор фактов и предложения.

Не входит: юридическая экспертиза лицензий конкретных курсов; платный контент как класс;
AI-слой публикации (исключён из Beta 1, `COS-REL-008` ADR-002).

## 3. Карта домена: «агрегация» — это три разных контура

Единого модуля нет. В репозитории живут три контура с разными контрактами и разными правилами:

```text
A. Реестр и агрегатор (что ЕСТЬ)          B. Поиск (что НАЙДЕНО)                    C. Публикация (что ВИДИТ пользователь)
learning-sources/registry.json            learning:discover (Google CSE)             competency.learningSourceIds
  -> aggregate.ts -> data/learning-sources  materials-agent (wikipedia/habr/medium/     -> release/beta-1.json (gate)
                                               internet-archive/stepik/youtube)           -> apps/web «Материалы»
  -> audited manually                       -> data/materials-agent/*.json (журнал)
```

| Контур | Вход | Выход | Пишет в продукт? |
|---|---|---|---|
| A. Реестр + `learning:aggregate` | 121 источник, `learning-source-links.json` | отчёт по открытым источникам | нет, только отчёт `data/` |
| B1. `learning:discover` | 4 поисковых шаблона × Google CSE | `data/learning-sources/discovered-*.json` | нет |
| B2. `materials:agent` / `materials:agent:queue` | accepted-блоки, 4 адаптера | `data/materials-agent/*.json` | нет, `writesToGraph: false` |
| C. Публикация | `competency.learningSourceIds` + реестр + source review | `apps/web/src/content/generated/beta-1.json` | да |

Ключевой факт: **A и B не связаны с C автоматически**. Единственный путь «найденное → в продукте» —
ручное добавление источника в `registry.json` и ручная связь в модели. Автоматический поиск за всё
время не добавил в реестр ни одного источника: в реестре `discoveredBy` = `user` у 118 записей,
`manual` у 3 и `search` — у 0 (`src/methodology/v1/learning-sources/types.ts:24`).

### 3.1. Сущности

| Сущность | Где | Что задаёт |
|---|---|---|
| `LearningSourceRecord` | `learning-sources/types.ts:13` | id, url, kind, access, authority, status, topics, summary, lastChecked |
| `Material` | `competency/materials/collect.ts` → журнал | найденный кандидат с `discoveredFor`, `links`, `status: candidate` |
| `learningSourceIds` | `competency/model/competencies.json` | **единственный источник истины** для публикации; собирается из двух tracked-мест |
| `learningSourceLink` | `competency/model/learning-source-links.json` | ручная связь + `rationale` |
| `SourceReviewDecision` | `release/beta-1-source-review.json` | 973 решения `accepted` (AI-assisted) |

Связи «компетенция → источник» ведутся не в одном месте, как заявлено в `COS-RES-022` §6.1, а в двух:
`learning-source-links.json` (132 записи, 103 уникальные компетенции, 325 пар без дублей) **и**
`competencies-extra.json` (68 из 88 компетенций уже несут `learningSourceIds`). `model:sync` их
объединяет (`competency/model/build.ts:34-53`), поэтому в модели сейчас 78 источников и 347 пар,
покрыто 121/122 компетенции. Свежие 50 пар из `1d31b95` в модели ещё **не** отражены: `competencies.json`
не пересобирался, поэтому продукт их не видит. Это влияет и на то, куда дописывать найденные
источники, и на отчёты покрытия.

### 3.2. Публикационный gate (что реально доходит до пользователя)

`scripts/release/lib.ts` пропускает источник в продукт, только если он:

- `status: active`, не `aggregator`, не `discoveryOnly` (`scripts/release/lib.ts:462-465`);
- имеет `summary` (`:490-499`) и `lastChecked` не старше 30 дней (`release/beta-1.json:28-35`);
- получил review-решение `accepted` по паре «профессия/компетенция/источник» (`scripts/release/lib.ts:471-489`).

Сейчас **96 из 325** пар в link-файле не имеют `accepted`-решения, в том числе **все 50 пар**,
добавленных `1d31b95`: они не попадут в публикацию даже после пересборки модели, пока не появится
решение source review. Это второй ручной шлюз после реестра.

Порог по количеству — `minActiveSources: 1` (`release/beta-1.json:34`): одной карточки достаточно,
чтобы компетенция считалась опубликованной. Разнообразие форматов и языков не проверяется.

### 3.3. Что видит пользователь

Раздел «Материалы» раскладывает источники на 5 подразделов
(`apps/web/src/lib/content.ts:224-230`): курсы (`course-platform`, `school`), видео (`video-channel`,
`video-playlist`), статьи (`blog`, `aggregator`), справочники (`reference`), кейсы (`portfolio-case`).

Фактическое содержимое `apps/web/src/content/generated/beta-1.json` (54 уникальных источника, 642 строки
«профессия × компетенция × источник»):

| Формат | Строк | Доля |
|---|---:|---:|
| Курсы (`course-platform`, `school`) | 571 | 89% |
| Справочники (`reference`) | 51 | 8% |
| Кейсы (`portfolio-case`) | 9 | 1,4% |
| Видео (`video-channel`) | 7 | 1,1% |
| Статьи (`blog`) | 4 | 0,6% |
| `aggregator` | 0 | 0% |

## 4. Сценарии и роли

| Сценарий | Как устроен сейчас | Где ломается |
|---|---|---|
| Исследователь ищет новый источник | `learning:discover` (нужны ключи Google CSE, 4 профессии) или `materials:agent` (4 адаптера) → журнал в `data/` → глазами смотрит человек | найденное некуда «сдать»: нет команды промоушена в реестр, нет дедупа с реестром |
| Исследователь добавляет источник | руками правит `registry.json` + `learning-source-links.json` | дубли и мусор не отлавливаются до `learning:validate`/`learning:map` |
| Источник «стареет» | `learning:audit` пишет отчёт в `data/`, реестр не обновляет (`cli/audit.ts:26`) | через 30 дней gate начнёт резать публикацию; чинится руками |
| Материалы для компетенции | link-файл + `competencies-extra.json` → gate → карточка | по факту одна-две карточки, часто «курс-платформа» общего назначения |
| Материал «принят» в каталог | `catalog.materials` = 39: порог relevance ≥0.7 + free/freemium, без вердикта и ревью (`materials-agent/accept.ts`) | 579 кандидатов → 39 принято; нет оценки полезности, бейджей и возможности оспорить |

## 6. Пробелы и риски

### 6.1. Поиск не подключён к реестру (блокирует рост покрытия)

Факты:

- `materials:agent` пишет журнал с `writesToGraph: false` (`materials-agent/agent.ts:66`);
  приёмка `materials:accept` кладёт материалы в каталог по порогу relevance ≥0.7, но вердикта
  «полезно/не полезно», уверенности, бейджей и возможности оспорить — нет;
- `learning:discover` сохраняет кандидатов с пометкой «в реестр автоматически не добавляются»
  (`learning-sources/cli/discover.ts:37`) и не умеет нормализовать их в `LearningSourceRecord`;
- форматы `Material` (журнал агента) и `LearningSourceRecord` (реестр) несовместимы: разные id,
  нет `authority`/`professionIds`/`summary`, нет `duplicateOf`; конвертера нет;
- дедуп между найденным и реестром отсутствует; в агентской очереди дедуп только по `canonicalUrl`
  внутри одного прогона (`competency/materials/collect.ts:130-141`).

Свежий пример, подтверждающий разрыв: коммит `1d31b95` добавил 50 пар «компетенция → источник»
в `learning-source-links.json`, и агрегатор сразу показал 295 строк и пробелы Motion 3 / UXR 6 / UXUI 6.
Но `competencies.json` не пересобирался, `release:build` не запускался, `source-review` для новых пар
не обновлялся: в продукте по-прежнему 54 источника и 642 строки, а 50 новых пар не имеют
`accepted`-решения (96 из 325 пар без решения всего). То есть «нашли и связали» ≠ «опубликовали».

Следствие: найденное живёт в `data/` и теряется. Это главная причина, почему открытых источников
осталось 55, а не сотни.

### 6.2. Стратегия поисковых запросов слишком слабая

Факты:

- `LEARNING_SEARCH_QUERIES` покрывает 4 профессии из 12 (`learning-sources/search.ts:1-6`),
  запросы — общие фразы уровня профессии (`motion design free courses`), не компетенции;
- для отсутствующих профессий `discover` падает с «Нет search queries» (`cli/discover.ts:19-20`);
- Material Agent ищет по названию компетенции и `titleEn` и не использует определение, компоненты
  и теги (`competency/materials/collect.ts:123`); на выходе — статьи «вообще про тему»;
- нет языковых вариантов, нет форматов (курс/видео/гайд/разбор), нет site:-ограничений по
  доверенным доменам, нет негативных ключей (вакансии, зарплаты, «купить курс»);
- проверка качества на живых данных: в `data/materials-agent/it-motion-review.md` для компетенции
  «Взаимодействие с инженерами и правовые основы» найдены «Правовые основы защиты данных…» и
  «Социология права», для «3D-анимация и риггинг» — «Настоящее 3D-искусство»; связей у таких
  материалов 0, но они занимают слоты выдачи.

Причина: запрос строится из одного поля, а фильтрация релевантности происходит уже после того,
как лимит выдачи исчерпан.

### 6.3. Видео и бесплатные курсы структурно не находятся

Факты:

| Источник | Состояние | Следствие |
|---|---|---|
| YouTube | в `competency/sources/registry.json:98` — `status: planned`, `requiresEnv: YOUTUBE_API_KEY`; в `materialSourceIds` всех 12 профессий отсутствует (`sources/professions/it.motion.json:18-23`) | видео не собирается |
| YouTube адаптер | всегда ставит `language: "other"` (`materials/sources.ts:328`), а `collect` выбрасывает `other` (`collect.ts:128`) | даже с ключом **все** видео отбрасываются |
| Stepik | в реестре `status: degraded`; в `materialSourceIds` отсутствует | бесплатные курсы не собираются |
| Medium | тег угадывается из первых двух слов названия (`materials/sources.ts:422-435`) | шум, а не статьи по теме |
| Internet Archive | запрос `title:(<query>)` (`materials/sources.ts:174`) | слишком узко, часто 0 результатов |
| Habr | при `fl=en` отправляется тот же русский запрос (`materials/sources.ts:350-370`) | англоязычная выдача нерелевантна |
| `learning:discover` | Google CSE, только 4 профессии | новые домены не появляются |

Итог по форматам: в 55 открытых источниках 33 course-platform, 13 blog, 5 reference,
2 video-channel, 1 school, 1 кейс. Продукт обещает подразделы «Видео» и «Статьи»
(`content.ts:224-230`), но видео — 7 строк из 642 (1,1%), статьи — 4 строки (0,6%).

### 6.4. Нет измерения релевантности и полезности

Факты:

- в схеме реестра нет ни одного поля качества: relevance, level, duration, freshness контента,
  engagement, language-confidence (`learning-sources/types.ts:13-38`);
- `relevance` 0..1 существует только в LLM-схеме классификации материала
  (`competency/llm/schemas.ts:53-61`), то есть оценивает «подходит ли материал компетенции» постфактум,
  а не ранжирует выдачу поиска;
- агрегатор считает компетенцию покрытой, если к ней привязан хоть один источник
  (`aggregate.ts:136`); поэтому общие платформы «покрывают» по 10–18 компетенций
  (`practicum-design-catalog` — 18, `figma-design-basics` — 18, `greatlearning-uiux` — 16);
- нет метрики precision/полезности и нет gold-set прогона: `tests/learning-aggregate.test.ts`
  проверяет только фильтры, а не качество выдачи;
- в журнале Material Agent нет причины отказа и оценки релевантности: только `issues`
  (`materials/classify.ts`).

Следствие: «больше» можно измерить, «лучше» — нет. Любое изменение сейчас нельзя сравнить с текущим.

### 6.5. Правила агрегации расходятся с правилами публикации

| Правило | `learning:aggregate` (открытые) | Публикация Beta 1 |
|---|---|---|
| Доступ | только `free`/`freemium` (`aggregate.ts:42,98`) | любой `active`, включая `mixed` и `paid` |
| Авторитет | агрегаторы допускаются | `authority !== aggregator` |
| `summary` | не требуется | обязателен |
| review-решение | не требуется | обязательно |
| Объём | 55 открытых / 295 строк | 54 источника / 642 строки |

Пользователь видит «Яндекс Практикум» (`mixed`) в карточке, хотя отчёт называет его не открытым;
и наоборот, отчёт показывает агрегаторы, которые в публикацию не попадут. Одно слово «открытый»
означает в проекте две разные вещи. Среди 54 опубликованных источников: 30 `free`, 5 `freemium`,
11 `mixed`, 8 `paid` — то есть продукт показывает и платное, а отчёт про «открытое» его не видит.

### 6.6. Свежесть и эксплуатация

- `learning:audit` обновляет только `data/learning-sources/audit-*.json`, не реестр (`cli/audit.ts:26`);
  `lastChecked` в реестре лежит в диапазоне 2026-10-22…10-28, `registry.updatedAt` — 2026-10-28;
- gate режет источники старше 30 дней (`release/beta-1.json:32`), то есть при отсутствии ручного
  аудита публикация начнёт деградировать без изменений в контенте;
- robots проверяется только в `learning:topics` (`learning-sources/robots.ts`), `learning:audit`
  и discovery его не проверяют;
- нет расписания, нет кэша для аудита, нет rate-limit политики для адаптеров (только retry

- ключи поиска не описаны в `.env.example` (там только `DEEPSEEK_API_KEY`), хотя нужны
  `GOOGLE_CSE_API_KEY`/`GOOGLE_CSE_CX` (`cli/discover.ts:21-26`) и `YOUTUBE_API_KEY`.

## 7. Решения (приняты 2026-11-03)

Ответы на вопросы зафиксированы; реализация — [`COS-REL-009`](../12-release/COS-REL-009-Materials-Review-and-Confirmation.md).

| Вопрос | Решение |
|---|---|
| Глубина | **2–5 материалов на каждый формат** (курс, видео, статья, справочник, кейс); меньше — только после исчерпания лимита попыток (3 раунда на формат), с явной пометкой `insufficient` в отчёте. |
| Провайдеры | Только **официальные API/RSS**: Wikipedia, Habr, Internet Archive, Stepik, YouTube Data API, Google Programmable Search. HTML-скрейпинг, обход paywall/robots и неофициальные прокси — запрещены. |
| Кто ревьюит | **Агент-методолог** (LLM-пасс `E`): ранжирует, выносит вердикт `accept/confirm/reject` с причиной и уверенностью, пишет аудит. Правило №7 файла роли уточнено: полезность материала оценивать можно, уровни компетенций — нет. |
| Роль LLM | LLM **ранжирует и принимает сам**; сомнительное получает бейдж «Подтвердить». Подтверждать и блокировать могут только **залогиненные**; порог — доля от активных залогиненных (5% на блок с min 2 / max 10, 10% на подтверждение с min 2 / max 15). |
| `mixed` и доступ | **Показываем всё** по умолчанию — «Бесплатно», «Часть бесплатно», «Бесплатное и платное», «Платно», «Доступ не проверен». Отчёт «открытые» остаётся строгим free/freemium, продукт показывает ограниченный доступ с меткой. |

## 8. Рекомендации

Порядок — по отдаче на вложенное время. Решения 2026-11-03 сдвигают границу: **LLM ранжирует
и принимает материалы сам**, человек и сообщество подтверждают или блокируют сомнительное.
Структурные решения (компетенции, уровни, приоритеты) остаются за человеком; полные тексты
не копируются; paywall/robots не обходятся (`COS-RES-017` §4, `agents/AGENTS-material-agent.md`).
Детали и лимиты — [`COS-REL-009`](../12-release/COS-REL-009-Materials-Review-and-Confirmation.md).

### P0 — подключить поиск к реестру и продукту (1–2 недели)

**R1. Единый контракт кандидата и promotion-path.** *(Сделано 2026-11-03: `sources:expand` — `SourceCandidate`, нормализация/дедуп/скоринг, промоушен в реестр.)*
Новый тип `LearningSourceCandidate` (url, canonicalUrl, title, provider, kind, language, access,
проф/компетенция, query, relevance, whyUseful, provenance) + команда `learning:candidates`
(поиск → нормализация → дедуп → аудит → кандидаты) и `learning:promote` (кандидат → запись
реестра со `status: planned`, `discoveredBy: search`). Пересечение с реестром и внутри выдачи
считается по canonical URL + нормализованному домену/пути + похожести названия; дубли помечаются
`duplicateOf`, а не молча теряются.
*Критерий приёмки:* один прогон для профессии даёт JSON кандидатов в формате реестра; `learning:validate`
проходит; повторный прогон не создаёт дублей; ни один кандидат не попадает в публикацию без review.

**R2. Генератор поискового плана (детерминированный, с тестами).** *(Частично 2026-11-03: контекст компетенции и запросы под интенты/языки — `discovery/context.ts`; расширение по тегам/навыкам — дальше.)*
Вход — компетенция (title, titleEn, definition), компоненты и теги; выход — набор запросов:

- форматы: `course`, `tutorial`, `гайд`, `разбор`, `лекция`, `как сделать`, `free`;
- языки: ru и en (не только titleEn);
- `site:` по доверенным доменам из реестра и открытым библиотекам (Stepik, YouTube-каналы,
  документация, университетские OCW);
- негативные ключи: вакансии, зарплаты, «купить», «записаться», карьера, резюме;
- запросы по тегам/навыкам, а не только по названию блока.

*Критерий приёмки:* у каждой из 122 компетенций ≥4 запроса; снапшот-тест плана; ни одна профессия
не падает без шаблонов (сейчас 8 из 12).

**R3. Починить и включить видео/курсы.** *(Частично 2026-11-03: провайдеры Wikipedia/GitHub/Brave/YouTube в `sources:expand`; Google CSE остался только для поиска по списку сайтов — режим «весь интернет» отключён в 2026; включение YouTube/Stepik в `materialSourceIds` — дальше.)*
YouTube: не хардкодить `language: "other"`, определять язык по `defaultAudioLanguage`/`defaultLanguage`
или эвристике и не выбрасывать молча; `relevanceLanguage`; ключ в `.env.example`.
Stepik: фильтр бесплатных и языка. Habr: `queryEn` при `fl=en`, score/просмотры — в ранжирование,
а не в текст описания. Medium: заменить угадывание тега на курируемые домены/ленты.
Internet Archive: поиск по ключевым словам, не по `title:`. Включить `stepik` и `youtube`
в `materialSourceIds` всех профессий.
*Критерий приёмки:* на прогоне UX/UI и Motion появляются видео и бесплатные курсы; доля `other`
в выдаче — 0; все 12 профессий имеют полный список адаптеров.

**R4. LLM ранжирует и принимает (Pass E).** *(Сделано 2026-11-03: `materials:verify`, приёмка по вердикту.)*
Сначала дешёвый отбор: `relevanceScore` = лексическое совпадение (title+description vs
title/definition/теги) + авторитет + свежесть + язык + формат + сигналы вовлечённости; топ-20
на формат уходит в LLM. Методолог-пасс `E` возвращает `verdict` (`accept`/`confirm`/`reject`),
`confidence`, `usefulness`, `whyUseful`, `reason`, `flags`. Принять без бейджа — только при
`accept` + `relevance >= 0.7` + `confidence >= 0.7` + открытый доступ; пограничное — в выдачу
с бейджем «Подтвердить»; явно нерелевантное — отклонить с причиной. В журнал писать причину
отказа, чтобы решения были проверяемы.
*Критерий приёмки:* ручная выборка 20 кандидатов даёт ≥60% «да, полезно»; доля ошибок среди
принятых без бейджа ≤10%; у каждого отклонённого есть причина.

**R5. Лимиты покрытия и состояние попыток.** *(Сделано 2026-11-03: `materials:coverage`, `coverage-state.json`.)*
Цель — **2–5 материалов на каждый формат** на компетенцию: `min 2`, `target 3` (foundation — 5,
optional — 2), `max 5`. Поиск по формату — не больше 3 полных раундов запросов; после этого статус
`insufficient` с числом попыток и причиной (`no_source` / `no_relevant` / `budget`) и cooldown 30 дней.
Состояние попыток хранится между прогонами, отчёт `materials:coverage` показывает таблицу
«компетенция × формат: принято / цель / попытки / статус». Меньше минимума — только через
`insufficient`, без маскировки пробела.
*Критерий приёмки:* повторный прогон в тот же день не повторяет исчерпанный формат; отчёт
показывает дату следующей попытки; ни один формат не уходит в бесконечный поиск.

### P1 — измеримость и регулярность (месяц)

**R6. Оценочный контур (gold set).** Взять 121 компетенцию и 347 пар «компетенция–источник» из модели
(`competencies.json`, после merge) как положительные метки. Метрики: precision@5 найденного против gold,
покрытие (компетенции с ≥1 квалифицированным источником), доля форматов, доля ru, доля свежих.
Зафиксировать базовую линию до изменений и прогонять при каждом изменении discovery.
*Критерий приёмки:* отчёт метрик генерируется командой и сохраняется в `data/learning-sources/`.

**R7. Агрегатор v2.** Покрытие считать не «есть хоть одна ссылка», а «есть N квалифицированных
источников с relevance ≥ порога, среди них ≥1 первичный и ≥1 не-курс». В отчёте по каждой
компетенции — топ-5 с оценкой и причиной полезности; пробелы остаются честными.
*Критерий приёмки:* исчезает «ковровое покрытие» общими платформами; отчёт объясняет каждую ссылку.

**R8. Свежесть и здоровье ссылок.** `learning:audit` пишет статус/`lastChecked`/`httpStatus`
обратно в реестр; еженедельный прогон; robots-проверка и в аудите; кэш; битые ссылки — в отдельный
список на замену. *Критерий приёмки:* gate не режет по давности без ручных действий; отчёт
показывает битые/деградировавшие ссылки.

**R9. Расширение семейств источников.** Точечно (не «агрегаторами»): open courseware и
университетские курсы, YouTube-каналы/плейлисты по профессии, документация инструментов
(Figma, After Effects, Blender, Cinema 4D), RU-библиотеки (Статьи/видео на русском), профильные
издания (NN/g, Smashing, A List Apart, Figma Learn и т. п.). Для каждого — `access`, `robots`,
`authority`, `discoveryOnly` по правилам `COS-RES-022`.
*Критерий приёмки:* +50 курируемых источников, из них ≥10 RU-first и ≥15 видео.

**R10. Бейдж «Подтвердить» и подтверждение ресурсов.** *(Сделано 2026-11-03: модель `SourceReview`, API, бейдж и модалка.)* Сомнительные материалы (LLM `confirm`,
`confidence < 0.7`) публикуются с бейджем «Подтвердить» и подсказкой «Ресурс не подтверждён —
помоги подтвердить его актуальность». Модалка на существующих стилях: «Да, подходит» /
«Не подходит» с причинами (не по теме, недостоверный, ссылка не работает, платный или закрытый,
другое). Подтверждать и блокировать могут только залогиненные; порог — доля от активных залогиненных
(блок: 5% с min 2 / max 10; подтверждение: 10% с min 2 / max 15), 1 блокировка ниже порога — «спорный». Решения хранятся в БД и
выгружаются в пайплайн (`reviews:export`), чтобы блокировки переживали пересборку.
Метки доступа — понятные: «Бесплатно», «Часть бесплатно», «Бесплатное и платное», «Платно»,
«Доступ не проверен».
*Критерий приёмки:* сомнительный ресурс виден с бейджем; голос пользователя меняет статус без
перезагрузки; заблокированный ресурс исчезает и из следующей сборки; метка `mixed` объясняет,
что именно открыто.

### P2 — продукты и масштаб (квартал)

**R11. Апгрейд публикационного gate.** По решению 1 (2–5 материалов на формат) — поднять порог до 2–3 источников,
добавить разнообразие форматов (курс + статья/видео), проверку качества `summary` (содержательный,
не шаблон) и `rationale`. `minActiveSources: 1` оставить только для `optional`-компетенций.
*Критерий приёмки:* у опубликованной компетенции ≥2 источников и ≥2 форматов.

**R12. Обратная связь из продукта.** Событие `source_click` уже собирается (`scripts/metrics/report.ts`);
добавить к нему «сохранил/открыл/дошёл» и учитывать клики как слабый сигнал ранжирования
(не как доказательство качества). *Критерий приёмки:* отчёт «доля кликов по топ-1/топ-3»
и «материалы без кликов» доступен.

**R13. Единый реестр источников.** Свести два реестра (`competency/sources/registry.json` — адаптеры;
`learning-sources/registry.json` — свидетельства) к одному контракту или явно документировать
границу и общий namespace id. *Критерий приёмки:* нет двух источников с одинаковой ролью и разными схемами.

**R14. LLM-расширение запросов.** Генерировать варианты формулировок и переводы, но проверять
лексическим скорингом и ручной выборкой; бюджет — только на топ-N после дешёвого фильтра.
*Критерий приёмки:* precision@5 не падает при росте выдачи.

### Авто-расширение ресурсной базы (сделано 2026-11-03)

Результат первого полного прогона по 11 профессиям (Brave Search, ≈670 запросов free-тарифа):
335 компетенций-участков, 2 010 хитов, 350 кандидатов, 236 accept / 105 confirm / 9 reject;
после quality gate (confidence ≥ 0.75 + фильтр заголовков) записано 41 новый источник
(36 active, 3 planned, 2 blocked), 157 пар обновлено/добавлено, gate PASS. После spot-check
удалены 3 нерелевантных источника (`scan-interfax.ru`, `sendsay.ru`, `sidorinlab.ru`),
реестр — 159 источников (125 active), решения source review — 1 151.
Сервисные команды: `sources:remove`, `sources:access`, `reviews:decide`, `sources:provider-test`. Метки доступа проставлены у 32 из 38 авто-источников; 6 остались `unknown` до ручной проверки. 

`npm run sources:expand` — официальные API (Wikipedia extlinks, GitHub Search; Google CSE и YouTube —
при ключах) → нормализация URL, классификация вида, скоринг, дедуп с реестром → опциональное
LLM-ревью (`--classify`: accept/confirm/reject) → промоушен в `registry.json` (`status: planned`,
`discoveredBy: search`) и связь с компетенцией в `learning-source-links.json`; `--audit` проверяет
HTTP и переводит в `active`/`blocked`, `--review-decisions` добавляет AI-assisted решения source review.
Домен, который уже есть в реестре, не дублируется — он связывается с новой компетенцией.
Dry-run по умолчанию: реестр и модель меняются только с `--write`.
