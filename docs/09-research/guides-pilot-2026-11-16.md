# Агент разборов знаний и навыков — пилот 50 пунктов UX/UI

## 1. Что сделано

Доработан контентный агент: вместо короткого пересказа он готовит **подробный разбор из 3–5 разделов**
(что это; зачем в работе; как применять по шагам; пример из источника; на что обратить внимание),
складывает валидные разборы в **отдельный кластер знаний** и умеет работать в рамках квоты поиска.

Конвейер (`npm run guides:agent`):

1. **План запросов** — LLM на батч из 15 пунктов: короткий RU-запрос + EN-термин.
2. **Поиск** — Brave; **сначала RU**, EN только если русский поиск не дал пригодного источника;
   запасной короткий запрос по сущности, если длинная формулировка не нашла.
3. **Фильтр** — deny-list (вакансии, соцсети, карьерные сайты), эвристическая оценка домена и позиции.
4. **Загрузка и отбор** — страница → текст; порог тематической релевантности (совпадение названия пункта
   с заголовком/первыми абзацами), язык, объём, наличие заголовков; до двух источников на пункт.
5. **Синтез** — JSON `{status, sections[]}` строго по источнику; EN переводится по смыслу; при
   недостатке материала — `no_data`.
6. **Валидатор** — 3–5 разделов, 180–1400 символов на раздел, 900–6000 всего, русский, без ссылок,
   без «уровня/оценки», без обрыва; одна попытка починки.
7. **Кеш** — поиск, страницы и ответы LLM в `data/guides/.cache`; повторный прогон почти бесплатный.
8. **Кластер** — `src/methodology/v1/guides/content/it.json`: `id → {status, sections, sources, generatedAt,
   promptVersion, review}`. Это отдельная сегментируемая база знаний, а не часть релизной публикации.

Команды: `npm run guides:agent -- --profession uxui --limit 50`. Сырой прогон — в `data/guides/` (gitignore).

## 2. Доступность API и бюджет поиска

| Провайдер | Статус |
|---|---|
| Brave Search | ✓ HTTP 200; после пополнения счёта лимит 50 запросов/с (заголовок `x-ratelimit-limit: 50, 0`) |
| Wikipedia | ✓ ключ не нужен |
| YouTube RSS | ✓ без ключа |
| GitHub | ! 403 без токена |
| YouTube Data API / Google CSE | — ключей нет |

Расход: **v3 — 56 запросов, v4 — 2 запроса** (52 из кеша). При остатке ~$1.26 на Brave хватает ещё
примерно на 120–150 пунктов (с учётом RU-first и кеша). Полный прогон остальных пунктов UX/UI
(~120) укладывается в остаток; другие профессии — после пополнения.

## 9. Полный прогон по всем профессиям — 2026-11-17

После пополнения счёта Brave прогнан весь корпус знаний и навыков публикации. Перед прогоном агент
доработан под объём: `--profession all` (UX/UI первым), `--all`, `--skip-existing` (не пересобирать
готовое и не дублировать общие для профессий теги), `--concurrency 5` (параллельные пункты при
сериализованной записи кластера), честный учёт токенов/стоимости по пункту, чтение `.env.local`
из npm-скрипта. Заодно исправлен баг выборки: пункты за «пустым» кругом дедупликации терялись
(на полном прогоне это 5 вхождений / 2 уникальных пункта — покрыты другими профессиями).

```bash
npm run guides:agent -- --profession all --all --skip-existing --concurrency 5 --max-cost 12
npm run guides:audit
```

- **Аудит привязки к источнику** (`npm run guides:audit`): медиана **0,907**, среднее 0,886;
  ниже порога 0,6 — **14 пунктов (2%)**: кандидаты на вычитку (Spline/Unreal, адаптивные макеты

- **Структурных замечаний нет**: валидатор пропустил все 711 разборов (3–6 разделов, длина, язык,
  нет ссылок и «уровней»).
- **`no_data` — честный отказ**, причины: 20 — нет тематически совпадающего источника (API, MCP,

  валидатор. Для интерфейса это штатное состояние «Данных пока не хватает», не пустое место.
- Все 711 разборов имеют хотя бы один источник; `generated/guides.json` собран `release:build`
  и совпадает с кластером (тест `tests/study-marks.test.ts`).
