# COS-LEG-004 — Согласия: как фиксируем и предоставляем (Beta 1)

> **Что это.** Рабочий регламент: какие согласия собирает AXIONA, где и в каком виде они фиксируются, как выгрузить доказательства для субъекта ПДн и для РКН, что показываем в аккаунте. Не юридическое заключение: сроки и формулировки подтверждает юрист. Связанные документы — `COS-LEG-002` (политика), `COS-LEG-003` (cookie), `COS-REL-008` (ADR-022, ADR-026).

## 1. Зачем это нужно

По ч. 3 ст. 9 152-ФЗ бремя доказывания согласия лежит на операторе: недостаточно «баннер был на сайте», нужно показать, что конкретный субъект в конкретный момент принял конкретную версию текста. Это проверяется при обращении субъекта, при запросе РКН и в споре. Поэтому согласие фиксируется на сервере, а не только в cookie браузера.

## 2. Что считаем доказательством

Минимальная запись должна позволять ответить: **кто, на что, по какой version, когда и не отозвал ли**.

| Поле | Смысл | Где |
|---|---|---|
| Субъект | `userId` → email | `ConsentRecord.userId` |
| Вид согласия | `TERMS`, `PRIVACY`, `ANALYTICS`, `MARKETING` | `ConsentRecord.kind` |
| Версия документов | `LEGAL_VERSION` на момент согласия | `ConsentRecord.version` |
| Дата предоставления | `grantedAt` | `ConsentRecord.grantedAt` |
| Дата отзыва | `revokedAt` (пусто — действует) | `ConsentRecord.revokedAt` |

Дополнительно доказательством служат: версия текстов документов в репозитории (`legal.ts` + `docs/10-legal/*`), дата публикации, запись в decision log. Рекомендация юристу: хранить утверждённые редакции текстов как неизменяемые версии (тег/копия) — тогда `version` однозначно указывает на текст.

## 3. Какие согласия и где фиксируются

| Согласие | Когда | Как фиксируется | Отзыв |
|---|---|---|---|
| Условия (`TERMS`) | При погашении ссылки из письма (первый и повторный вход) | `ConsentRecord` с версией из токена | По запросу через `hi.axiona@protonmail.com`; отдельного UI в Beta нет |
| Политика (`PRIVACY`) | Там же | `ConsentRecord` с версией из токена | По запросу через `hi.axiona@protonmail.com` |
| Аналитика (`ANALYTICS`) | Выбор в cookie-баннере; переносится в аккаунт при входе | `POST /api/consent` → `ConsentRecord`; cookie `axiona_consent` для самого баннера | **UI в «Аккаунте»**: «Только необходимое / Разрешить аналитику» (`ConsentControls`); запись получает `revokedAt` |
| Маркетинг (`MARKETING`) | Не используется в Beta | — | — |

Ограничение: решения анонимного посетителя (до входа) живут только в cookie `axiona_consent` + `axiona_aid`; в `ConsentRecord` они попадают при входе. Для закрытой Beta с известными приглашёнными это приемлемо; для публичного запуска — отдельная запись анонимных решений (см. §7).

## 4. Механика в продукте (2026-11-10)

- `POST /api/consent` `{"decision":"all"|"necessary"}` — same-origin, ставит cookie `axiona_consent` (180 дней) и пишет `ConsentRecord` для вошедшего; невалидное решение → 400, чужой Origin → 403.
- `POST /api/auth/verify` — после входа переносит текущее решение из cookie в `ConsentRecord` (`recordAnalyticsConsent`), чтобы у приглашённого с первого входа была запись.
- `/account` — раздел «Согласия и версии документов»: вид, версия, дата, отзыв; кнопки изменения решения.
- `/admin/users/consents/export` — CSV для owner (`users:read`): email, kind, version, grantedAt, revokedAt. Без сессии — 401.
- Код: `apps/web/src/app/api/consent/route.ts`, `lib/auth.ts` (`recordAnalyticsConsent`), `components/account/ConsentControls.tsx`, `app/admin/users/consents/export/route.ts`.

## 5. Как предоставляем

### 5.1. По запросу субъекта ПДн

1. Запрос приходит на `hi.axiona@protonmail.com` (канал должен быть реальным — см. `reports/legal-gaps-2026-11-10.md` §5.4) или в отзыве через форму.
2. Инженер выгружает CSV по пользователю (owner-доступ) или выполняет запрос:

   ```sql
   select u.email, c.kind, c.version, c."grantedAt", c."revokedAt"
   from "ConsentRecord" c join "User" u on u.id = c."userId"
   where u.email = 'subject@example.com' order by c."grantedAt";
   ```
3. Ответ субъекту: выписка по согласиям (что, когда, версия, отзыв) + сведения о данных и сроках по политике. Срок ответа — 10 рабочих дней с возможным продлением на 5 (ст. 20 152-ФЗ), итог — на `hi.axiona@protonmail.com`.
4. Факт запроса и ответ фиксируются в переписке; удаление по запросу — через `/account` или вручную с проверкой.

### 5.2. Для РКН / проверки

- Выгрузка `/admin/users/consents/export` (CSV) + версии документов из репозитория + описание мер защиты (runbook §3.3 legal-отчёта).
- Для каждого пользователя видно: вход = TERMS/PRIVACY, баннер/аккаунт = ANALYTICS, отзыв с датой.

### 5.3. Проверка вручную

```sh
# страница аккаунта показывает записи и кнопки отзыва
open https://app.axiona.world/account
# CSV доступен только owner
curl -i https://app.axiona.world/admin/users/consents/export   # 401 без сессии
```

## 6. Сроки хранения

- Записи согласий хранятся, пока действует согласие, и после отзыва — разумный срок для доказывания (ориентир: 3 года, срок исковой давности; **подтвердить у юриста**).
- Удаление аккаунта удаляет `ConsentRecord` каскадом вместе с пользователем; факт удаления и основание фиксируются в переписке/журнале.
- Cookie `axiona_consent` живёт 180 дней и не заменяет серверную запись.

## 7. Ограничения и что осталось

- **Анонимные решения** до входа не попадают в БД — только cookie. Для публичного запуска добавить запись анонимных согласий (по `anonId`) и срок её хранения.
- **Согласие при входе** — пассивная строка «Нажимая «Войти»…» без чекбокса; юридический вопрос по ст. 9 ч. 1 (ред. 156-ФЗ) открыт (`legal-gaps` §4.4).
- **MARKETING** не реализован и не используется.
- **Версии текстов**: нужно хранить утверждённые редакции неизменяемыми (сейчас version — строка `LEGAL_VERSION`; после sign-off поднять версию и зафиксировать тексты в release-теге).
- **РКН** и **email-контур** (Resend/Protonmail) — отдельные блокеры T-005, не закрываются этим регламентом.

## 8. Ответственные

| Роль | Действие |
|---|---|
| Владелец/оператор | Утвердить тексты и версию, отвечать на запросы субъектов, назначить сроки |
| Инженер | Поддерживать запись, выгрузку и UI; при смене документов поднимать `LEGAL_VERSION` |
| Юрист | Проверить формулировки, сроки хранения и достаточность доказательств |
