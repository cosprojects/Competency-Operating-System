## 9. Контур: варианты

### Вариант A — весь продукт на VDS в Москве, корпоративный сайт на Vercel (рекомендую)

- `axiona.world` остаётся корпоративным сайтом на Vercel.
- `app.axiona.world` (или `test.axiona.world`) — A-запись на VDS в Москве.
- На VDS: Docker Compose (Next.js app + PostgreSQL 16 + Caddy), TLS, бэкапы.
- Один origin для продукта: cookie, auth, SSR, API и БД работают без CORS и без межконтурных запросов.
- VDS: 2 vCPU / 4 GB / 40–80 GB SSD, Ubuntu LTS, Docker, только 22/80/443, SSH-ключи, firewall, nightly `pg_dump` + проверка restore.
- Email — РФ-провайдер через HTTP API; `APP_URL=https://app.axiona.world`; на старте `AUTH_REGISTRATION_DISABLED=1`, инвайты.

Почему: текущее приложение — SSR-монолит с Prisma/Postgres. Разносить фронт и БД дороже, чем поднять весь продукт на VDS.

### Вариант B — Vercel-фронт + VDS-БД/вычисления (не рекомендую для MVP)

- Vercel-функции должны ходить в Postgres на VDS по публичной сети: latency, connection limits, необходимость защищать БД, cross-border processing.
- Server Components/API на Vercel всё равно выполняют вычисления; чтобы «вычисления» были на VDS, нужен отдельный API-слой или reverse proxy, то есть переделка приложения.
- Для Beta это лишний риск и время; возвращаться к разделению имеет смысл после product-market fit.

### Вариант C — Vercel только для статики, продукт и API на VDS

- Потребует переписать страницы на клиентский fetching, настроить CORS/cookies, потерять часть SSR/SEO.
- Имеет смысл только при отдельном маркетинговом фронте; не для текущего MVP.

### Домен

- Сейчас: `axiona.world` — корпоративный сайт (Vercel), `app.axiona.world` — продукт (VDS).
- После Beta: если продукт становится главным, можно поменять местами корень и `company.`/`axiona.biz`; это отдельное решение с 301.
- `axiona.biz` не блокирует: American phone у регистратора — проблема регистратора, а не продукта. Поддомен `axiona.world` уже даёт «один домен» без покупки нового.

### Что сделать на VDS

1. Купить VDS с московским IP, статическим IP, Ubuntu LTS.
2. Docker + Compose + Caddy; Postgres 16 в контуре; порт БД не публиковать.
3. DNS: `app` A → VDS IP; TLS Caddy.
4. `.env.production`: `APP_URL`, `DATABASE_URL`, `EMAIL_*`, `OWNER_EMAILS`, `LEGAL_VERSION`, `AUTH_REGISTRATION_DISABLED=1`.
5. `db:deploy`, health, nightly backup + restore test, monitoring.
6. Legal: оператор, политика, РКН; тест только на инвайтах/тестовых данных.
