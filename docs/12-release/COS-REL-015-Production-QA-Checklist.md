# COS-REL-015 — Production QA checklist (T-009)

> **Назначение.** P0-чек-лист приёмки production-контура `app.axiona.world` перед приглашением дизайнеров (T-012) и релизом v0.2.0 (T-013). Полный отчёт прогона — `reports/production-qa-2026-11-10.md`; legal-блокер — `reports/legal-gaps-2026-11-10.md`.
>
> **Границы.** Проверяем production-контур и сценарии реального пользователя. Не входит: полная E2E-автоматизация, нагрузочное тестирование, пентест, проверка кода на уязвимости (только внешняя поверхность атаки).
>
> **Статусы.** ✅ PASS · ❌ FAIL · ⚠️ WARN (не блокирует) · ⬜ MANUAL (нужен ручной шаг/сессия/почта). Колонка «Baseline» — результат прогона 2026-11-10, а не целевое состояние.

## 1. Как проводить

1. **Автоматический смоук** (чтение + негативные запросы, без записи данных):

   ```sh
   npm run qa:smoke -- --json /tmp/prod-qa-smoke.json
   # или напрямую: node scripts/qa/production-smoke.mjs
   ```

   79 проверок: доступность, редиректы, защита API без сессии, заголовки, legal-страницы, ассеты, robots/sitemap, шум сканеров.
2. **Браузерный QA** (headless Chrome + axe-core WCAG 2.1 A/AA, 360 и 1280 px, скриншоты):

   ```sh
   npm run qa:browser -- --out docs/12-release/reports/screenshots/production-qa-$(date +%F)
   # или напрямую: node scripts/qa/browser-a11y.mjs
   ```

3. **Ручные шаги** — только с тестовым аккаунтом, которым владеет команда (`owner`/`qa@`). Никаких ПДн реальных людей, реальные отзывы и удаления — только тестовые.
4. Каждый дефект — issue в GitHub с шагом воспроизведения, ожидаемым/фактическим, скриншотом и severity. Дефект закрывается только повторным прогоном **(Fix → Rerun → Evidence)**, не «на глаз».
5. Результат фиксируется в `reports/production-qa-<дата>.md`; скриншоты — в `reports/screenshots/production-qa-<дата>/`.

## 2. Severity и gate

| Severity | Определение | Что с релизом |
|---|---|---|
| P0 | Невозможно войти/пользоваться: вход, сессия, сохранения, legal-контур отсутствует | Блокирует T-012 и T-013 |
| P1 | Ломает сценарий у части пользователей или создаёт неверные данные/ошибки в консоли | Блокирует T-012, если задевает основной путь |
| P2 | Заметный дефект без потери функции: контраст, SEO, дубли заголовков, UX-состояния | Можно выпускать, но фиксируется до публичной Beta |
| P3 | Косметика, технический долг | Бэклог |

**Gate T-009:** все P0-пункты ✅ или явно ⚠️ с подписью владельца; нет открытых P0/P1; legal-страницы без черновика (T-005 sign-off); mobile 360px без горизонтального скролла; axe без critical и без serious на основном пути.

## 4. Ручные проверки, которые нельзя закрыть смоуком

- Доставка письма в Gmail/Яндекс/Mail.ru, папка «Спам», внешний вид письма.
- Одноразовость и истечение magic link (15 минут), повторное использование.
- Полный вход/выход/смена email/удаление аккаунта — требуют почтового ящика и сессии.
- Сохранения и статусы на двух устройствах, профиль, модалка удаления.
- Отзывы и админ-действия (owner), `AdminAudit`, CSV-экспорт, метрики.
- Клавиатурный сценарий и screen reader.
- DNS/SPF/DKIM/DMARC, бэкап/restore и мониторинг — на VDS, не из рабочей машины.
