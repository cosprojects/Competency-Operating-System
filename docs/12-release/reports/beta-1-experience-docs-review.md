# Beta 1 — аудит документации Experience Architecture

Дата: 2026-10-28. Область: `docs/04-experience-architecture/` (13 документов, `COS-EAR-000`…`COS-EAR-012`) + реестр `COS-REL-007`.

## Итог

Раздел описывал **целевой** опыт COS (навигатор, профиль, диагностика, чат, паспорт компетенций) и не содержал ни одной границы с тем, что реально работает. Дизайн, опирающийся на эти документы, проектировал бы несуществующий продукт: текущая Beta — карта компетенций, а не диагностика.

Актуализировано 13 документов и реестр:
- в каждом документе — раздел «Состояние и место в дорожной карте»: что работает сегодня, чего нет, к какому этапу `COS-BP-005` относится документ, терминологическая граница `COS-BP-007` §7.2;
- `COS-EAR-012` получил §13 «Связь с дорожной картой» — таблицу «сценарий → этап → статус»;
- устранены расхождения с кодом (БД диагностики, обучающий контент, пути к данным, мёртвые имена файлов);
- в `COS-REL-007` добавлены `COS-EAR-012` и группа целевых документов, книга переведена на `COS-EAR-000`.

Критичных противоречий не осталось; 5 вопросов требуют продуктового решения (раздел «Требует решения»). Разделы о дорожной карте синхронизированы с планом первого года `COS-BP-009`: ближайшие объекты дизайна — экраны Beta (этап I), затем профиль компетенций и прогресс (M5–M6), затем Pro (M7–M10).

## Проблемы

### Критично (вводило в заблуждение)

1. **Диагностика описана как текущий MVP** → `COS-EAR-009` (весь документ), `COS-EAR-010`, `COS-EAR-011`, `COS-EAR-008` → в коде этих потоков нет, `COS-REL-008` ADR-001 прямо исключает их из Beta → *исправлено*: раздел 1.1 в каждом документе, статус «следующий слой».
2. **Нет единой точки «что реально работает»** → весь раздел `04`, где каждый документ описывает целевой опыт → дизайн не может отличить реализованное от желаемого → *исправлено*: `COS-EAR-012` как опорный документ, ссылки из каждого документа и из реестра.
3. **Ментальная модель «навигатор» подана как действующая** → `COS-EAR-002` §The Core Mental Model → противоречит лендингу «не оцениваем уровень, не строим маршрут» → *исправлено*: прямая формулировка «Beta 1 — карта, а не навигатор».
4. **«Обучающего контента в MVP нет»** → `COS-EAR-011` §2 → в Beta 1 материалы — ядро продукта: раздел «Материалы», 29 уникальных источников → *исправлено*.
5. **Неверная БД для модели диагностики** → `COS-EAR-011` §3 указывал `prisma/schema.prisma` для состояний узлов, доказательств, ответов и подписок → этих моделей там нет; они в `prisma/assessment.schema.prisma`, который Beta не использует → *исправлено*.

### Важно (мешало работе)

6. **Имена файлов нарушали `COS-010` §4** → `COS-EAR-005-Navigatio.md` (опечатка), `COS-Experience_Architecture_Book.md` (подчёркивания, нет id) → ломает проверку стандарта и ссылки по id → *исправлено*: переименованы, книге присвоен `COS-EAR-000`.
7. **8 документов без frontmatter** → `COS-EAR-001…007` и книга → `COS-010` §2 требует обязательные поля; §11.1 разрешает добавлять их вместе с содержательной правкой → *исправлено*.
8. **Корнер-кейсы не сопоставлены с реализацией** → `COS-EAR-010` → часть случаев (регистрация, аккаунт, мобильное поведение) актуальна уже в Beta, но документ этого не различал → *исправлено*: таблица `C-ID → что в Beta → файл`; отдельно отмечены нереализованные `C-52` (истёкшая ссылка), `C-65` (отзыв согласия), `C-71` (загрузка), `C-74` (без JS).
9. **«Канвас» означает две разные вещи** → `COS-EAR-008` §6 vs реальный раздел `/canvas` со статическими схемами → риск, что макет графа сделают по канвасу схем → *исправлено*: оговорка в разделе 1.1.
10. **Нет сопоставления «сценарий → этап дорожной карты»** → `COS-BP-005` §17 и `COS-BP-007` §7.1 существовали отдельно от `04` → риск проектировать этапы VII–IX в Beta → *исправлено*: `COS-EAR-012` §13.
11. **Реестр не отражал фактическое состояние** → `COS-REL-007` → не было `COS-EAR-012`, книга числилась по старому имени → *исправлено*.

## Требует решения (смысловые правки не делались)

1. **`COS-EAR-007` и сценарии Beta.** Ни один из пяти канонических паттернов не описывает то, что делает текущий продукт (просмотр карты, открытие компетенции, сбор материала). Варианты: добавить паттерн «Explore / Reference» или явно зафиксировать, что Beta лежит вне набора, а паттерны применяются с этапа VII. Сейчас граница отмечена, но решение не принято.
2. **`COS-EAR-004`: профиль-центричная IA против контент-центричной Beta.** Шаг 1 `COS-BP-007` («профиль и прогресс») потребует решить, становится ли профиль точкой входа и как это меняет IA карты. Документ этого решения не содержит.
3. **Терминология в глоссарии `COS-005`.** Разграничение `COS-BP-007` §7.2 («профиль/прогресс» — самоотметки, «паспорт компетенций» — отложенная диагностика) не внесено в глоссарий; там же нет терминов Beta 1 (профессия, компетенция в профессии, материал/источник, избранное, статус изучения, гейт материалов). Правка вне запрошенной папки — не делалась.
4. **Статусы целевых документов.** `COS-EAR-008…011` остаются `Draft`; формально они не «решение». Нужно решить: оставить `Draft` до этапа VII или перевести в `Approved` как целевую архитектуру следующего слоя.
5. **`COS-EAR-000`.** Книге присвоен id `COS-EAR-000` и она переименована. Если для сводных книг в проекте задуман другой формат id — это стоит зафиксировать в `COS-010`, иначе следующая книга получит id иначе.

## Ограничения проверки

- Проверялись документы и код в рабочем дереве на коммите `35c5f2d`; продуктовые мотивы решений по интерфейсу не восстанавливались.
- Во время аудита в репозиторий пришёл коммит `35c5f2d` (`COS-BP-009`, ADR-012/013). Документы `04` синхронизированы с ним; содержимое BP-009 и ADR не аудировалось — это вне области запроса.
- Поведение под нагрузкой (rate limit в памяти, недоступная БД, мобильные браузеры) не проверялось запуском — утверждения о поведении взяты из кода.
- `docs/11-scenarios/*` (целевые сценарии диагностики) остаются вне аудита: они относятся к тому же отложенному слою и на них действует та же граница, но запрос касался только `04-experience-architecture`.
- Скрипт проверки ссылок и frontmatter из `COS-010` §9 до сих пор не реализован — проверка выполнялась вручную.
