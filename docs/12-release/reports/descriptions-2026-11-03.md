# Субагент описаний — отчёт о раскатке

- Дата: 2026-11-03
- Область: `it.aidesigner` → все 13 profession view
- Команды: `npm run descriptions:agent`, `npm run descriptions:validate`
- Итог: **13/13 профессий, 132/132 компетенции, 658/658 уникальных тегов — 0 ошибок валидатора**

## 1. Проблема до изменений

- все 12 profession view не имели собственного описания — release-сборка подставляла
  «<Название>: структура компетенций, знания, навыки и учебные материалы.»;
- **93 тега** начинались с `Понимание:`/`Умение:` и дублировали название;
- **281 тег** был короче 40 символов;
- не было автоматической проверки качества описаний.

## 2. Что реализовано

- `src/methodology/v1/competency/descriptions/`:
  - `validate.ts` — детерминированный quality bar;
  - `apply.ts` — атомарная запись в view, canonical/extra, catalog;
  - `agent.ts` — сбор контекста, LLM-вызовы, валидация, отчёт.
- LLM: `DESCRIPTION_PROMPT_VERSION = descriptions-v1`, схемы `descriptionResponseSchema`,
  промпты профессии/компетенции в `llm/prompts.ts`.
- CLI:
  - `npm run descriptions:agent -- --profession <slug|all> [--write] [--all] [--limit] [--budget-usd]`
  - `npm run descriptions:validate [--profession <slug|all>]`
- `npm run aggregate --write` выполняет стадию описаний после `model:sync`; отключается `--no-descriptions`.
- `agents/AGENTS-description-writer.md` — ролевой контракт.
- CI: `descriptions:validate` добавлен после тестов.
- Профессиональное описание UX/UI хранится в `model/professions/descriptions.json`
  (у UX/UI нет отдельного view-файла); release-сборка читает этот слой.

## 4. Примеры «до → после»

**Профессия AI-дизайнер**

- было: `AI-дизайнер: структура компетенций, знания, навыки и учебные материалы.`
- стало: `Проектирует цифровые продукты и визуальные коммуникации, встраивая генеративные модели и AI-агентов в исследование, сценарии, интерфейсы, прототипы и производство контента. Отвечает за связь дизайн-решений с ценностью продукта и за проверку качества AI-результата.`

**Знание «Design system governance»**

- было: `Понимание: Design system governance.`
- стало: описание сути governance через правила, роли и синхронизацию дизайн-системы с кодом.

**Навык «Типы исследований»**

- было: `Качественные и количественные методы исследования и их назначение.`
- стало: `Качественные методы раскрывают мотивы и контекст, а количественные дают измеримые данные; вместе они помогают выбирать способ проверки гипотез.`

## 5. Ограничения и ручной spot-check

- 10 новых AI-блоков и их теги были созданы ручной курацией; описания сгенерированы по контексту
  компонентов/источников — нужен выборочный human-review.
- Часть описаний общих компетенций обновилась глобально (они используются несколькими профессиями).
- Валидатор проверяет форму и запреты, но не научную точность; LLM не должна была выходить за контекст.
- 658 — уникальные теги; с учётом повторного использования тегов в разных блоках в каталоге 727 вхождений.
