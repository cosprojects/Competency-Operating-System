### P0 — блокирует Beta

**F-01. Вход и выход не завершаются: абсолютный редирект на `https://localhost:3000`.**
`POST /api/auth/verify` возвращает `303 Location: https://localhost:3000/...`; `POST /api/auth/logout` — `https://localhost:3000/`; `POST /api/auth/email-change` — то же. Причина: редиректы собираются из `new URL(path, request.url)`, а Next 15 в этом контуре строит `request.url` из внутреннего адреса `localhost:3000` (не из `Host`/`X-Forwarded-Host`; проверено и с явными `X-Forwarded-*`). Симптом из контура: после нажатия «Войти» по ссылке из письма браузер уходит на localhost и вход не завершается; токен при этом уже погашен (`consumeLoginToken` до редиректа).
Где: `apps/web/src/app/api/auth/verify/route.ts:6-7`, `api/auth/logout/route.ts:9`, `api/auth/email-change/route.ts:10,14,51`.
Рекомендация: собрать редирект от `process.env.APP_URL` (fallback — `request.url`), например хелпер `absoluteUrl(path)` в `lib/auth.ts`; альтернатива — `experimental.trustHostHeader: true` в `next.config.mjs`, но её надо осознанно принять (Host приходит только от Caddy). После фикса — регрессионные проверки QA-56/57 в смоуке и полный вход/выход вручную.

> ⚠️ Это противоречит `reports/vds-2026-11-10.md` («владелец вошёл»). Нужно перепроверить, как именно проверялся вход: текущий production-контур не может завершить magic-link вход в обычном браузере. Если вход тестировали до этой конфигурации Caddy или вручную ставили сессию — отчёт T-007 надо скорректировать.

### P1 — блокирует приглашение дизайнеров

**F-02. `robots.txt` и `sitemap.xml` указывают на корпоративный `axiona.world`.** `sitemap.xml` отдаёт URL `https://axiona.world/...`, `robots.txt` — `Sitemap: https://axiona.world/sitemap.xml`. Причина: оба файла статически генерируются на этапе `next build`, а в Docker builder-стадии нет `APP_URL`; fallback в коде — `https://axiona.world`. Там же fallback для welcome-письма: ссылки в письме могут вести на корпоративный сайт. Где: `apps/web/src/app/robots.ts:4`, `app/sitemap.ts:5`, `lib/email.ts:25`.
Рекомендация: передать `APP_URL` в builder-стадию (`ARG APP_URL` + `ENV APP_URL` в `Dockerfile`) **и** сменить fallback на `https://app.axiona.world`; либо сделать metadata-роуты динамическими. Проверить welcome-письмо после входа.

**F-03. Hydration-ошибка на `/professions`: вложенные `<a>`.** В SSR-разметке 12 вложенных якорей (`a.profession-tile > … > a.icon-button`) — невалидный HTML: браузер закрывает внешний `<a>` раньше, React падает с #418 и пересобирает дерево. Побочный эффект: клик по звезде у неавторизованного пользователя ненадёжен. Где: `apps/web/src/components/ProfessionSearch.tsx:103` (Link-плитка) и `:128` (Link-иконка входа внутри). Рекомендация: плитка — не `<a>`, а контейнер с растянутой ссылкой-оверлеем (`::after`) либо звезда — `<button>` с переходом через `router.push`; вложенные интерактивные элементы запрещены.

**F-04. На `/professions` нет `<h1>`.** Страница начинается с поиска и `h2`. Нарушает структуру документа и SEO. Где: `apps/web/src/components/ProfessionSearch.tsx` (заголовок не рендерится). Рекомендация: видимый или `sr-only` `<h1>` («Профессии дизайнера»), `h2` групп оставить.

### P2 — исправить до публичной Beta

**F-05. Контраст текста ниже WCAG AA.** Токен `--soft: #8a99ad` даёт 2.9:1 на белом (нужно 4.5:1 для 12–13 px). Используется в `.coverage-text` (в т.ч. «Покрытие Beta», проценты), `.section-panel .section-count`, подсказках полей формы отзыва. axe: 25–33 узла на `/professions` и `/professions/uxui`, 2 на `/feedback`. Где: `apps/web/src/app/globals.css:19` (`--soft`), `:1247`, `:1428`, `:461`. Рекомендация: для текста 12–13 px использовать `--muted` (#5f6f85, 5.1:1) или затемнить `--soft` до ≥ 4.5:1 (≈ #6b7a90) и перепроверить axe.

**F-06. Ссылки в тексте различимы только цветом.** `/register`: ссылка «Войти» в абзаце «Уже есть аккаунт?» — `text-decoration: none`, отличие только цветом (`link-in-text-block`). Где: `globals.css:3738-3741`. Рекомендация: `text-decoration: underline` (или `underline-offset`) для ссылок внутри текста.

**F-07. Дубли security-заголовков и `X-Powered-By`.** HSTS, `X-Content-Type-Options`, `Referrer-Policy` отдаются дважды: Caddy (`Caddyfile:9-13`) и Next (`next.config.mjs:19-25`). На HTML присутствует `x-powered-by: Next.js`, хотя в конфиге `poweredByHeader: false` — стоит проверить, что образ собран из текущего коммита. Рекомендация: оставить один источник заголовков (обычно Caddy — TLS-терминатор), убрать дубли; разобраться с `x-powered-by`.

**F-08. `favicon.ico` → 404**, `<link rel="icon">` в HTML отсутствует. Рекомендация: `app/icon.svg`/`app/favicon.ico` в Next-конвенции.

**F-09. SSRF: `link-preview` следует редиректам без повторной проверки хоста.** Проверяется только исходный hostname; публичный URL может отредиректить на приватный адрес или `169.254.169.254`. Где: `apps/web/src/lib/link-preview.ts:139` (`redirect: "follow"`). Рекомендация: `redirect: "manual"` с повторной валидацией каждого шага (и/или проверка адреса после DNS-резолва), лимит редиректов.

**F-10. `/register` в режиме закрытой регистрации — тупик.** Страница обещает «Создай аккаунт», форма принимает email и показывает «Проверь почту», хотя письмо не уходит (`AUTH_REGISTRATION_DISABLED=1`). Для приглашённых путь — `/admin/users` (owner), не `/register`. Где: `apps/web/src/app/register/page.tsx:21`, `apps/web/src/app/api/auth/request/route.ts:57-64`. Рекомендация: при закрытой регистрации показывать состояние «Beta по приглашениям» с объяснением и ссылкой «Войти».

**F-11. Отзыв согласия на аналитику недоступен в интерфейсе; факт согласия не доказуем.** Решение хранится только в cookie (`client-analytics.ts:32`), `ConsentRecord` пишется только для TERMS/PRIVACY (`auth.ts:190-196`), `ConsentKind.ANALYTICS` не используется. Юридически это блокер T-005 (см. `legal-gaps-2026-11-10.md`, §4.1), технически — P2 с приоритетом до публичного запуска. Рекомендация: серверная фиксация согласия/отказа, кнопка «Изменить согласие» в футере/аккаунте.

**F-12. Контакты и голос расходятся с документами.** В футере и письмах — `hi.axiona@protonmail.com` (`SiteFooter.tsx:40`, `email.ts:105,126`), в legal-документах — `support@`/`privacy@axiona.world`. Cookie-баннер и часть ошибок на «вы» («с вашего согласия», «Попробуйте позже») при голосе продукта на «ты» (COS-COM-010). Рекомендация: один канал на домене продукта, тексты — по COS-COM-010.

### 10.1. E2E-проверка входа и сессионных сценариев

Чтобы не ждать почтовый ящик, в production-БД был создан временный пользователь и одноразовый токен (тот же `LoginToken`, что выдаёт приложение), пройден полный путь и данные удалены после проверки.

| Шаг | Результат |
|---|---|
| `GET /auth/verify?token=…` | 200, страница «Подтверди вход» |
| `POST /api/auth/verify` | 303 → `https://app.axiona.world/profile`; `__Host-axiona_session` c `Secure; HttpOnly; SameSite=Lax`, Max-Age 30 дней |
| `/profile`, `/account`, `/saved` с сессией | 200; профиль содержит «Сохранения» и «Последние сохранения» |
| `POST /api/favorites` (профессия `uxui`) | 200 `{saved:true}`, `/saved` показывает сохранение |
| `POST /api/study-status` (`LEARNING`) | 200 `{status:"LEARNING"}` |
| `POST /api/feedback` | 200 `{ok:true}`, отзыв создан |
| `/admin` под обычным пользователем | 307 на `/` (нет capability) |
| `POST /api/auth/logout` | 303 на `/`, cookie очищена; `/profile` → 307 `/login?returnTo=/profile` |

Временные данные (пользователь, токен, сессия, сохранения, статусы, отзыв) удалены из production-БД после прогона; остаточных записей нет. **P0 «вход не завершается» закрыт фактически, а не только по заголовку `Location`.** Доставка письма через Resend в реальный ящик по-прежнему требует ручной проверки (QA-A02).

**Что всё ещё требует ручной проверки:** доставка magic link в Gmail/Яндекс/Mail.ru, приглашение через `/admin/users`, удаление аккаунта, смена email, статусы отзывов и админ-действия, метрики, DNS/SPF/DKIM/DMARC, бэкап/restore. Открытые дефекты: F-11 (согласие на аналитику не пишется на сервер), F-12 (Protonmail vs `support@`), F-13 (deep-link админки), F-14 (мелочи).
